# 持久化故障与角色异常核验

日期：2026-09-20。V1-03／Gate C 的本批故障子项**候选验证通过，尚未部署**。同一候选两轮完整回归 418/418、双端类型检查及 20 条历史兼容核对通过；不代表完整 Gate C 或正式生产版通过。

## 发现与修正

本批不是修改单次运行数据，而是修改所有同类场景的规则：

- **共享 Journal 写入失败**：旧候选已复现“新提交失败，但已派发角色继续运行”。现在先同步封闭该 Journal 所属已绑定根会话、问题和子角色的执行权限，再通过官方取消与托管执行范围回收。其他独立 Journal 与未绑定 Agent 不受此通知影响。
- **故障界面不明确**：使用现有只读 Connection 通道传递受会话约束的故障类别。客户端撤下缓存快照，原生状态显示“存储待恢复”，说明下一步和退出仍未确认；不增加聊天窗口或写接口，不展示原始错误、路径或堆栈。
- **子角色模型／报告异常**：原来角色虽已失败，顶部仍可能显示普通推进状态。现在仅对当前版本、未结束运行中的异常角色标明“角色执行异常”和需要处理；阻止继续派发。查看原生调用错误、停止本轮并重新确认后才能新建运行，不将异常伪装成 QA 失败或自动消耗业务返工。

## 不可混同的状态

“执行权限已撤销”“停止请求已发出”“物理进程已退出”“退出证据已持久化”是不同事实。

真实 SQLite 写锁实验中，测试命令及受控后代确实退出；但 Journal 无法保存退出观察，旧行仍保持不变。新读取器恢复该行时仍须保留退出未知，不因为本次测试看到了进程消失就补写成功、取消、验收 FAIL 或已停止。

写入失败发生在写入前或写入已完成但确认返回失败时，均不向订阅方发布新可信快照。冷读取以实际保存内容为准；不重置 revision、删记录、自动批准、回滚文件或自动重启。时长记账无法确认使用独立类别，不等同于正常预算耗尽。

## 兼容与剩余范围

没有增加持久化事件或变更 Journal 行协议。故障类别为只读错误响应的可选元数据；角色异常提示从已保存的任务与角色状态派生。旧解析器能读记录，不代表旧运行时具备新的停止和准入规则。

写锁实验和模拟 I/O 异常**不能解释历史 disk I/O error 的根因**，也不是所有磁盘故障模式的证明。历史 I/O、55 条目录 diagnostic、Journal／原生会话／文件一致性与脱敏导出、生产资源配置及长运行开销仍需补齐。C/D/E 未通过，当前 3080 未加载本批修正。
