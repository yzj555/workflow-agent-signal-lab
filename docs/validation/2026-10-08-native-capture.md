## 首次安装失败及修正

首次干净构建 526/526 通过，但实际安装采集返回 `catalog-duplicate-or-cycle`／未完成。原因是官方 `session/list` 在这一历史副本中也列出子会话，初版采集器将子 ID 同时出现在列表与子目录误判为循环。

修正后每个父会话只读取一次，从独立官方目录边归类根和子会话；真正的重复父属和循环仍拒绝。新增两项回归，最后两次 528/528 和安装后验证通过。首版构建／归档及失败捕获保留，不覆盖或描述为成功。这个失效说明单元通过不替代安装后验证。

最终安装包的字节以以上摘要为准；首版同编号内部试制归档的摘要不同，未发布、未获准接入，不能仅凭 RC 编号拿它部署。

## 当前 Host 版本差异仍未闭环

只读核查发现：本机全局 DSH 入口是指向源码 `apps/cli` 的 Junction，当前磁盘上的 CLI 元数据为 **0.2.0-rc.2**，源码 HEAD 为 `639ed015397290b3745d163aafe02ffee4aa3f84`。它与此候选固定的 **0.1.5-rc.1** 验证组件不同。

本批核查时 3080 仍为先前已观察的新进程 PID 72752；其实际已加载版本、Profile 和插件组成**未由本维护测试认证**。磁盘 package.json 不足以证明进程内版本，旧 writer 也不能认证新 Host。没有操作真实 3080 的停止、启动、预算、配置或历史迁移。

因此汇总保留 `needs-attention-current-host-compatibility`。下一步先针对新官方组件做独立兼容检查／适配，再准备用户已选的独立生产 Profile。不得把固定旧 Host 上通过的安装测试直接当成当前全局入口兼容或生产接入许可。
