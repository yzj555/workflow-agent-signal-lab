## 本批实现

- 新 SDK 安装层使用官方 `dsh-agent-preset` 声明，不再扫描旧预设根目录。生成器从包内元数据和组合声明生成第四项默认停用行，保留 `!!js`；启用时不覆盖 registry 的 default、selectedDefault、其他预设或未来字段。
- 新版必须显式携带 `presetAdmissionProtocol: 1`。缺失、错误类型或未知协议拒绝，不能只修改 Host 版本字符串让旧包混入新版。
- 首阶段检查安装载荷、Profile、模块身份和配置，取得同一个 CAS writer；第二阶段在 controller 与预设依赖就绪后，审计实际 Loader 声明、注册正文、唯一活动 generation 和真实子树。
- 不在自身启动中等待整个 Host Loader，也不调用会反向等待 Host 的 roster/composition 清单；只等待声明 fiber 和预设子树。避免 guard／engine 自等待。
- 第二阶段完成前，Journal 可能已打开，但工作流根绑定和新工作流工具变更保持封闭；UI 依赖完成后的 verified 服务。第二阶段失败撤下 controller、关闭 Journal 并释放 owner。准入撤销后，已有工作流根也不能提交新变更；其他预设不受影响。这是发行就绪检查，不是需求确认或执行门禁授权。

主工程已加入配置、发行生成与 engine／preset 准入接线。新 SDK 的其余源码、依赖与测试适配仍在仓库外私有候选中；在线 `lib`、主依赖锁、原预设和既有 RC.7 没有替换。生成代码存在不等于已制作、安装或启用新版归档。
