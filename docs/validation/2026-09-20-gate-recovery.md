共用夹具对每次中断先核对精确自有子进程，再强停并保留真实 SQLite 记录；新 Host 必须先被旧 writer 标记拒绝。仅在证实该测试子进程退出后，测试控制者归档临时目录内的标记，绝不自动抢锁。各路径另外重复两个全新 Host 的冷启动，核对记录原值摘要、不产生模型派发或重复子角色。

未知状态、阻塞原因和处理方式由现有状态投影／显示回归核对；撤销的未完成／待清理状态同时有跨进程显示断言。同日真实页面只读检查的独立结果见 [激活摘要](2026-09-20-activation.md)。需要人工核实退出时保留 unknown；用户通过原生处置门禁结束旧 run，不构成进程退出证明。

## 本次确认的权限边界

1. **等待中的旧问题没有跨 Host 回答句柄。** 显式续接会取消旧门禁、生成新问题；旧 ID、拒绝或不明确回答都不能授予执行权。
2. **已持久化且仍匹配当前合同的批准不会仅因重启失效。** 但批准本身不会启动 Agent；重复确认被拒绝，必须显式推进，下一角色只派发一次。
3. **需求变更不能继承旧批准。** 尚无角色派发时更新合同会失效旧批准；已完成只读方案的运行不能原地覆盖合同，必须明确结束旧 run，再建立新 run、重走需求理解。旧合同和决定完整保留。
4. **源码或旧验收不等于当前交付。** 外部改动会阻止沿用旧 PASS；实现完成仍需完整的工程检查、代码审查和独立验收。
