## 修正的问题与保留的失败

1. **开发环境掩盖了模块来源。** 首轮构建目录嵌套在项目中，原生预设发现退回祖先的旧开发插件，官方请求身份登记分裂；同时测试导入了 npm 包未发布的内部客户端文件。首轮 460 个可发现测试中 402 通过、57 失败、1 取消，且未发现完整预期测试集。改为仓库外构建、同次构建的普通文件副本，并通过官方已发布浏览器入口验证连接；没有放宽官方冻结请求身份校验。
2. **只锁 CLI 不足以锁定 DSH 组件。** 官方范围依赖解析到了更新的子包。按上述固定源码基线锁定组件集合及 Zod／React；中间一轮 Zod 不匹配导致类型检查失败，保留日志。覆盖值只用于本工程和独立测试 Host，不写入用户 Profile。
3. **标准 Host 缺少插件的私有 SQLite 后端。** 真正独立的安装暴露了缺失依赖，不能靠开发目录补齐。Node 发布构建嵌入固定版本的官方 SQLite 实现；共享服务仍外置。随后补齐它依赖的 Schemastery peer，保留中间失败记录及官方 MIT 声明。
4. **归档与卸载细节。** pnpm 会规范化 `package.json` 末尾格式，初次安装核对发现摘要不一致；改为先生成其归档格式再取摘要。官方 remove 转发的 pnpm 不接受 `--ignore-scripts`，改用其支持的 `--config.ignore-scripts=true` 后再做完整演练；原失败没有算作卸载通过。
5. **最终采用真正的生产模式重跑。** v6／v7 已经各自 472/472 且归档一致，但 runner 当时使用 development 环境。修正后冻结为 v8／v9，重新完成上述全量、安装及兼容验证。本页最终摘要只对应 v8／v9，未把较早结果重新标记为生产模式证据。

没有因为安装失败而修改业务门禁、停止／未知语义、超时或历史数据。原失败和无效的嵌套 Host 演练均保留，不作为最终通过证据。
