# DSH 0.2 同安装包的文本返工与资源边界核验

结论：**DSH `0.2.0-rc.2`／插件 `1.0.0-rc.12` 在官方安装环境通过双 L0 文本返工、模型第 241 次调用前拒绝、Host 并发拒绝与取消结算，以及实际 30 分钟有效活动到限、原生只读工作流回放和完整冷快照核对。** 43 个安装载荷逐项等于已验收 RC.12；完整长跑单独完成，不以短跑或旧包结果替代。资源边界专项通过，正式环境及独立使用验收尚未完成，Gate C／D／E 未关闭。

独立生产 Profile 和完整保留旧档案的方案不变。核验只使用新的无凭据临时 Home、动态 loopback 端口和限定的本地脚本模型；没有创建生产环境、操作 3080、修改旧档案、调用外部模型、批准真实任务门禁或发布。

## 已完成的核验

| 场景 | 结果 |
| --- | --- |
| 双 L0 原生流程 | 两个根任务实际走需求确认、实现与验收；各因当前交付不满足 AC-1，从 verification 返回 implementation 一次，复验后均 PASS，revision 均为 47 |
| 角色工具边界 | 实际 AgentLoop 的根及子角色工具逐次对照控制层白名单；验收工作包不携带返工提示，结果来自当前交付文本，不是实现角色自报 PASS |
| 模型额度 | 当前正式 run 实际进入提供者的根请求恰为 240 次，第 241 次被前置拒绝；账目保持 240、blocked 为 root-model，不自动补额或重试，业务 outcome 保持 null |
| Host 并发与取消 | 两个根流已占满时第三根不进入提供者；仅发取消时仍占位，迭代器结算后才释放。原生 `/workflow-resources` 可读，后续明确用户消息才重新推进 |
| 原生只读界面 | 工作流页签显示当前事实、下一步、用户是否需操作、跳过及完成阶段与完成角色；只有一个原生输入框，pageerror 为 0 |
| 实际 HTTP 读取 | 短跑 42 次，完整长跑 7,010 次成功快照 RPC，包括两个交付样本和两根长跑会话的两组读取循环；不是两个独立浏览器标签，也不是服务 SLO |
| 有效活动到限 | 两根各记录 observedMs=1800000、blocked=active-time，预留为零、计时 owner 清空；收尾 overrun 分别 10／15ms，未伪造业务 FAIL 或自动补额续跑 |
| 退出与冷读 | 两个样本 Host 均正常退出 0、writer 释放；各自 5 行 Journal、全部 run 及 8 个完整根快照与退出前相同，官方解析作用域正常关闭 |

两根模型请求占位峰值为 2，子角色峰值为 2；四角色并行属于此前独立的 L1 工程样本，见 [主工程整合与工程运行](2026-10-08-dsh-020-canonical.md)。根请求占位指标不表示所有子角色模型流的总数。辅助原生标题请求单独保留，不冒充正式 run 额度。

短跑读取循环 p95 约 5.9ms、最大约 7.4ms，仅描述这个本机有限样本。有效活动分别约 11.1 秒，未触及时长上限；其取消用于收尾，不能据此声称实际 30 分钟到限通过。

## 回放与错误记录的边界

只读浏览器拦截了原生页面初始化的两次 `POST /api/session/create`，已有会话与工作流仍可打开。初版证据检查器误要求拦截列表为空，在未写通过回执前失败；原运行回执与检查失败保留，后续准确要求这两项初始化拦截，不开放写请求。因此本项只证明回放，不是完整聊天、建会话或可写交互验收。

样本保留一次故意触发的 Host 并发拒绝和三次取消造成的提供者中断，不能描述为“所有错误计数为零”。完整业务快照、请求次数、结算与冷回放核对通过；合成提供者和问答钩子不代表独立真实模型或用户验收。模型侧工具／工作包隔离不等于 OS 读取隔离。

本机短跑证据位于 `.dsh/activation/dsh-020-runtime-20261008/prepared-v5` 的 `run-v1`、`check-failure-v1.json` 和 `check-v1`；完整长跑位于 `prepared-v6` 的 `run-v1` 与 `check-v1`，途中观察另保留。两个样本分别使用新 Home，共享同一未修改探针和 RC.12 归档，不使用短跑数据作为长跑结果。原始日志与数据库不公开。

## 完整长跑结果与剩余工作

另一全新安装环境运行两个实际原生根流，维持只读快照循环，配置仍为 240 次请求、40 次命令、1800000ms 有效活动和原命令超时值。观察器允许的负载窗口为 1850000ms，实际约 1800701ms；两根到限中断并收敛，最后根流、角色、未确认角色占位全部为零。没有用加速时钟、降低额度或额外请求驱动替代实际长跑，也没有宣称完全消除调度延迟。

7,008 次持续循环读取的 p95 约 5.5ms、最大约 109.7ms，另两次交付快照均通过。测试 Host 采样 RSS 峰值约 324.8MiB，CPU 合计约 25.9 秒，事件循环 p95 约 32.0ms、最大约 78.7ms；CPU／RSS 不包含外部浏览器进程。期间有只读源码／证据核对和文档编辑，没有并行构建或另起测试 Host。这些是本机有限负载的观察，不是内存硬配额、长期无泄漏证明或满容量 SLO。

独立绑定检查重新核对归档、全部安装载荷、当前 Journal、正式 run 用量、拒绝／中断记录和完整冷回放。测试 Host 与观察器均已退出；本批仍未发现 3080 监听或生产目标目录，不能据此推断某个旧 Profile 已升级。

独立生产 Home／Profile 准备与激活、非实现者的真实模型任务、正式版本和许可选择仍按各自范围取得授权；历史不兼容及未知退出不因新环境通过而改写。整体准入见 [Production v1 清单](../operations/production-v1-status.md)。
