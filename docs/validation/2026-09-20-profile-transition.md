## 本批实现

新增离线 `capture`／`prepare` 维护入口，支持编号 RC 间升级、同版本重配置以及有精确归档目标的回退。流程保留原配置身份和资源策略，拒绝过期检查点、未知协议及未复核的配置变化，不安装、不启动、不回滚数据。

检查点与启动均使用运行时相同的原子 writer。启动 guard 持锁核对数据后，将同一个 owner 交给存储，避免“检查通过后释放，再被另一个写者插入”的间隙；关闭时待存储排空再释放。旧锁不自动回收。

完整回放在临时 SQLite 副本执行，比较原始记录、快照及所有 run 状态，禁止解析器静默丢字段。复制和遍历有限额；不修改原库、WAL 或 SHM，也不恢复备份数据库。

## 实际隔离验收

| 场景 | 结果与限定 |
| --- | --- |
| RC.2 → RC.3 → 最终 RC.5 | 通过官方安装路径，非空 Journal 保留；目标配置核对后实际启动 Web，原生工作流页签可见 |

| 过期检查点 | 使用新增记录之前的旧检查点被拒绝，当前数据未被覆盖 |
| 受控启动失败 | 仅在测试生成的启用 overlay 中加入注释，摘要失配；真实 Host 以 1 退出，未打开 writer，数据不变。不是破坏安装二进制或数据库的故障演练 |
| RC.6 → RC.5 | 使用含两条记录的当前检查点和精确 RC.5 目标归档；回退只换代码和启用方案。两条记录、完整状态、新增文件及原生压缩历史摘要完全不变 |
| 空闲停用 | 正常退出后去掉启用 overlay；工作流预设／UI 不加载，仍能在原生侧栏打开已有合成会话；一个原生输入框，0 页面异常，记录字节不变 |

五次启用页面检查以及停用检查均使用 headless Chromium，官方 Host 正常退出、没有强杀。页面校验包含原生工作流记录、需求待确认状态和单一原生输入框。浏览器阻断原生启动时的自动空会话创建请求，也阻断模型任务和变更类请求；这个预期阻断不计为成功创建新任务。

历史样本是标注为“未调用模型”的合成 v3 压缩原生会话；空 turn 只用于让原生页签可见。升级后第二条 Journal 样本不另建原生会话，不能冒充真实双任务或多 Agent 使用。全过程没有模型调用或真实门禁批准。
