## 界面验收不是实际模型验收

Web 使用临时 DSH_HOME、随机 loopback 端口和独立空工作区，不是用户正在打开的 3080。浏览器是独立自动化 Chromium，不能写成用户已在应用内浏览器验收。

合成样本明确标为“发布验收 · 合成只读回放”：测试 Journal 只含待需求确认记录，没有批准、派发或实现。为显示原生页签，测试会话另写入一个明确用于显示的空 turn 和合成标题；没有调用模型或工具。这些原生事件不是实际执行成功证据。

浏览器只打开既有合成会话和工作流页签，没有回答问题或批准门禁。首次声明确认仅写合成 Profile 的原生设置，API Key 选择“稍后配置”；因此不能笼统称整个测试 DSH_HOME 完全只读。原生启动尝试自动创建空白会话的 RPC 被拦截，随后由脚本打开既有样本；所有模型、门禁写入和外部浏览器请求均未放行。

合成 Journal 的字节摘要在启用、停用与漂移拒绝后始终一致。资源策略已在独立配置中接线，但本批没有模型负载，不能替代最终资源限制或独立真实使用验收。

## 修正与失败保留

- 第一次实际配置生成将官方 pnpm 安装路径当作不安全链接拒绝；改为对官方 bundle 路径取真实目标再冻结。私有数据／用户配置路径仍拒绝链接，不放宽写入边界。
- 第二次暴露官方 `loadOptionalPatches()` 对不存在的 home patch 返回 `undefined`，改为明确的空组合层。
- 查明默认 Web Profile 会进行 live 配置重载，而已满足的 guard 可能在后续重组中保留。本分发流程要求显式 `patchReload: startup`，不静默修改用户 manifest，也不声称支持热配置。
- 早期浏览器脚本误用了 `networkidle`、单包资源 URL、Session ID 当显示标题、固定首次引导顺序以及不存在的 DOM 类名；后续分别按照官方 SSE／组合资源／原生导航行为纠正。仅“入口已加载”或仍被初次引导遮挡的截图不计为完整界面验收。
- 中间构建、安装失败和浏览器失败全部保留，最终结论只对应 build-v4／v5、sample-v4 的 enabled-v8／disabled-v1／stale 证据，未覆盖旧失败。
