## 同归档的实际工程运行

使用官方安装后的 CLI／Host，而非只在开发组件中构造替身。模型响应来自显式限定的本地脚本提供者，执行的是实际官方 AgentLoop、工具、PowerShell 与托管进程；测试环境原生问答由合成钩子回答，不能算真实用户或独立使用验收。

| 场景 | 实际结果 |
| --- | --- |
| 两条 L1 工程同时运行 | 2 个根任务，工程测试／代码审查四个角色实际到达并发屏障；各自随后进行黑盒验收并交付 PASS |
| 角色与可见上下文 | 逐次核对实际模型工具集合；QA 只有冻结命令、工作包和报告工具，其工作包不包含实现源码 |
| 文件与命令证据 | 每个根有当前实现文件检查点和两条真实冻结命令；命令成功退出，当前文件内容匹配交付证据 |
| Host 占位 | 根任务峰值 2，角色执行峰值 4，`rootModelRequests` 峰值 2；最后占位全部归零。该模型指标是根请求占位，不是所有子角色流的总数 |
| 命令额度 | 实际执行 40 次，第 41 次前置拒绝；执行次数文件、账目和退出观察一致，不自动补额或重试，不捏造业务 FAIL |
| 命令超时 | 使用包内原值 120000ms，实际观察为 120031ms；托管句柄 `waitForExit` 确认退出，工具已结算、命令标为 interrupted，不冒充验收失败 |
| 退出后的重放 | 三个新环境的 2／1／1 行 Journal、全部 run 与完整快照均与退出前一致；writer 正常释放，Host 均正常退出 |

超时测试中的 Node PID 在运行结束后的额外 OS 查询中已不存在；该后置查询不是独立的精确停止时刻测量。120031ms 来自实际工具观察及托管退出屏障，不把它扩展成任意后台进程或 OS 级隔离保证。本批没有放宽命令时限、退出宽限或整轮策略。

首轮工程执行已经通过，但旧观察器在 Host 退出后直接导入运行库，因未建立 SDK2 官方解析作用域而冷读失败。保留原失败回执，使用归档自己的 `verifyProfile`／`withProfileResolution` 核对 peers 并在作用域内完成冷读与关闭；原现场冷读核对通过，随后另建新 Home 完整重跑通过。没有补开发链接、改包载荷、改数据库或删除断言。

本机证据为 `.dsh/activation/dsh-020-canonical-20261008/plan-v1`、`final-v1` 和两次 `dsh-020-canonical-20261008-rc12-v1`／`v2`；运行证据为 `dsh-020-runtime-20261008/prepared-v1` 的失败与冷读复核，以及 `prepared-v2`／`v3`／`v4` 的三条完整通过路径。最终绑定检查重新核对输入、原文件备份、载荷、归档、当前 Journal 和保留的构建／链接。

## 新版恢复矩阵的证据绑定

后续逐项审计两次已完成的 SDK2 全量日志，不以总数代替覆盖：220 个当前发行输入仍匹配冻结构建，四份恢复测试及共享夹具在两轮中执行，选取 28 个明确用例逐项为 ok、无跳过。两份测试工作区的实际运行库与归档 lib 摘要相同，安装依赖实际为 DSH `0.2.0-rc.2`。本项是已有新版执行证据的核对，不新增测试次数或生产 Host 中断。

| 既定恢复分支 | 两轮中的对应证据 |
| --- | --- |
| 等待第一道或第二道门禁 | 四种确认位置各三项，旧回答拒绝、持久化批准不自动派发、变更不继承授权 |
| 角色已分配但未报告 | 实际活动子模型中断，旧角色保持 unknown，不重新派发 |
| 文件写完但尚未检查 | committed implementation 与半写入分别核对，只明确续接当前下游 |
| 并行检查仅一方结束 | 审查保留，真实运行命令未知，不凭新 Host 空列表证明退出 |
| 返工完成但尚未复验 | 同角色身份、版本与一次返工记录保留，完整重新验收后才交付 |
| 撤销意图与文件事务中断 | 五个真实自有组件 Host 切点，原始现场保留，新确认或只清理，不重复提交 |
| 沉淀部分决定后中断 | 已采纳项保留，只重开待修订项，旧回答拒绝 |

共用夹具只强停自己持有的临时子进程；新 Host 先被旧 writer 拒绝，确认该进程句柄退出后归档临时标记，随后重复冷启，不自动抢锁。官方 AgentLoop、Questions、持久化与命令组件是真实 SDK2，模型和决定仍为合成提供者。新版七类机制矩阵有同一归档证据，不宣称 OS 掉电、物理磁盘损坏、任意进程树隔离或已对生产 Profile 强停验收。

本机绑定回执为 `.dsh/activation/dsh-020-canonical-20261008/recovery-audit-v1`；2026-09-20 的 [旧基线验收](2026-09-20-gate-recovery.md)仍保留原日期及范围，不倒签。
