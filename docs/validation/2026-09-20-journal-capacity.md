# 日志容量暂停与收尾空间核验

日期：2026-09-20。结论：V1-03／Gate C 的日志容量子项**候选验证通过，未部署**；不代表完整 Gate C 或正式生产版通过。

## 原问题与规则

旧构建存在两个已复现问题：满额历史仍呈现为普通可继续状态；没有累计预算账户的运行在模型请求准入处提前返回，未检查日志容量。两项旧版失败分别留档。

候选沿用原始硬上限，增加提前暂停线与有界提交：

| 项目 | 执行暂停线 | 硬上限／单批限制 |
| --- | --- | --- |
| 每个原生根会话的 Journal 事件 | 9000 条 | 10000 条 |
| 规范化 Journal 行的 UTF-8 JSON 内容 | 14 MiB | 16 MiB |
| 一次提交 | — | 最多 128 条事件／512 KiB 输入 |

达到任一暂停线后，该会话不能新增工作、模型执行请求、工具授权、角色派发、批准、返工或新 Run。最后一次合法提交仍完整保存；余量只接收既有工作的停止、退出、文件观察和中断收尾，或取消门禁／任务。不能通过预算补额解除容量暂停。

这是**每个会话的结构化行容量**，不是 SQLite 文件／WAL、对象备份或整个数据目录的磁盘配额。不会截断、归档后清空、删除旧记录或重置批准。

## 停止与交互

- 触顶后的持久化通知同步撤销本 Host 持有的执行权限，中断原生根响应、待答问题及对应后台角色；命令退出仍走官方托管执行范围核对。
- 文件检查点提交如果恰好触顶，在真正调用原生写工具前再次检查权限；确认请求提交如果触顶，不再展示无法生效的批准卡。
- “已撤销权限”“退出未知”“已核实停止”不能互换。容量拦截不产生业务 FAIL，不篡改验收账本，也不自动撤销已有文件。
- 顶部及工作流视图显示“容量暂停”、保存量和下一步；已完成阶段和历史结论仍保留，不能把仍标记 running 的旧记录解释为已停。
- 原生输入框的 `/workflow-capacity` 用于查看，`/workflow-capacity stop` 请求停止并核对。两者不调用模型；命令仅在工作流预设作用域注册，没有新增聊天窗口或写入 RPC。
- 对已经达到旧硬上限、连恢复观察都无法补写的历史，只保留原样并报告未确认退出；不让这一行封闭其他健康会话的 Journal。后续需按保留现场的恢复程序核对，不能靠新会话绕过未完成撤销或未知执行。

## 兼容与剩余边界

没有新增持久化事件或修改 Journal 行协议；容量状态从保存的行推导，是只读快照的可选字段。**旧版能够解析数据，不等于可以安全降级执行**：旧运行时缺少新的容量准入规则。激活／回退还必须核对目标版本是否保留这些安全边界，不能只验证 schema 可读。
