# Host 并发准入 v1

2026-09-20，开发候选，尚未部署。已完成同输入双轮 466/466，见 [独立验收记录](../validation/2026-09-20-host-admission.md)；以下边界只适用于一个 DSH Host 中此工作流预设的唯一控制器，不是整个系统或其他插件的资源沙箱。

## 限制对象

`hostAdmissionEnabled` 默认关闭，防止源码更新悄悄改变已有运行。生产候选显式开启，`hostMaxActiveRoots=2`、`hostMaxRoleExecutions=4`。参数有限且在关闭时也校验；子角色下限为 2，以容纳固定工程图的双角色验证波次。

“活动根范围”是当前根模型流、待提交的角色预留和持久化未结束角色涉及的根会话并集，不是打开的标签页数，也不是所有尚未交付的任务数。没有后台活动且模型已结束的用户等待不占位。最多同时有两个根模型流、四个子角色执行范围；两者不是同一个计数器。

| 事件／状态 | 占位处理 |
| --- | --- |
| 根 AgentLoop 模型请求 | 官方冻结请求、精确 Agent 绑定；模型供应商及累计预算扣次之前取得名额 |
| 根流取消 | 仅发取消信号不释放；迭代器实际结束的 `finally` 才释放 |
| 下一批角色可执行 | 整个波次同步预留；足够才落盘，之后由持久化 assignment 接管占位 |
| 角色派发前提交失败 | 没有调用原生启动，撤销临时预留；原存储故障机制仍封闭执行 |
| 报告已交、但未正常结束 | 继续占位；报告和业务结论不是退出证明 |
| 正在取消／停止未确认 | 保留占位；不能根据 `lease.active=false`、PID 消失或空列表释放 |
| 已确认结束但仍有未知命令 | 保留关联执行范围，直到命令的处置也明确 |
| 重启看到旧 running／unknown | 从已有 Journal 重建保守占位，不重派，也不丢掉历史计数 |
| 现有原生门禁明确人工结束 | 按用户处置放行新的范围；保留 ABANDONED、unknown 和 `exitConfirmed=false`，不伪称 Host 证实退出 |

历史占位已经超出新阈值时，不删除或挤出旧记录，不再派发新角色。已有占位根仍有最多两个同时根模型请求的核对通道；第三个新范围不能借核对名义执行。无需模型的原生命令始终可查看，真实推进仍受合同、权限和预算共同约束。

## 名额不足时的行为

名额不足返回可读错误，本次不派发、不自动排队、不自动补额。控制器对该原生根会话记住暂停：原响应不能循环尝试，后台完成通知也不能解封。名额释放后，须在后续原生 turn 观察到真正 `source.kind=user` 的消息，才允许重新尝试；新消息不是新的执行授权，原合同、门禁、版本、文件状态和预算仍须检查。

这个拒绝标记属于当前 Host 的响应防重试状态，不新增 Journal 协议；重启不自动创建或恢复 Agent，仍按既有冷恢复流程执行。是否具备名额始终重新从持久化范围核对，不从旧 UI 提示推断。

原生 `/workflow-resources` 仅显示开关、计数、尚未确认的角色数和占位的根会话 ID；不调用模型、不改历史。`/workflow-resources stop` 只收窄当前会话的权限并核对停止，不能停止其他根会话、扩容或抹除未知状态。仍使用 DSH 原生输入框，不新增聊天 UI。

## 接入与证据边界

- 接入点是本插件实际使用的 `llm/stream` 和 `startContinuable`／`sendMessage` 派发前，不使用另一个上游 worker-thread 引擎的并发配置冒充本路径约束。
- 子角色模型请求使用已持久化的角色名额，不重复计作根模型；仅精确匹配当前受控 Agent。
- 不限制其他预设或原生辅助模型调用，不声称约束远端供应商内部执行、Token 费用、全部内存、磁盘或 OS 进程数。单文件、检查点、日志及各层超时保留各自限制。
- 卸载先封闭准入并取消持有的根流；流未结算不得当作已释放。原有有限回收宽限和 writer 保留规则不变。
- 真实模型任务、线上启用、重启和发布仍需要具体授权；当前只做隔离验证。

初始定向证据：9 项单元／控制器用例通过；官方原生接口的 3 项专项首轮为 1 过／2 失败，原因是测试误读 `CommandExecution.result` 和 `latestReturn` 字段，改正后 3/3。后续暂停防自动重试、存储及卸载边界已补齐；最终新增 16 项、同输入双轮 466/466、20 条历史完整状态兼容。原始失败保留，未将这些隔离证据冒充线上激活或独立用户验收。
