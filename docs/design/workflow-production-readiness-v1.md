## 1. 生产 v1 的边界

生产 v1 不是通用自动化平台。它是用户显式选择 `工作流 Agent · Signal Lab` 预设后，由 DSH 原生对话承载交流、由插件工作流页签展示结构化运行状态的受控模式。

本次准入只支持：

- L0 文本交付；
- L1 当前工作区内的局部、跨模块或架构类工程变更；
- 已冻结的角色图：协调、只读方案、实现、工程测试、代码审查、黑盒验收；
- 固定的串并行路径和最多一次同范围返工；
- 用户权限域内的需求理解、执行、规则治理和文件撤销门禁；
- 本地、前台、逐字冻结的构建、静态检查和测试命令；
- 有来源证据、逐项确认、可修订、可停用的项目或预设级沉淀。

生产 v1 明确不支持：

- 任意 DAG、动态角色或开放式多 Agent 编排；
- L2/L3 高风险动作、发布、安装、升权、后台服务和进程控制；
- 网络、数据库、云资源或工作区外部系统的写入；
- OS 级源码读取隔离、网络隔离或进程隔离；
- 对冻结脚本间接产生的网络、进程、缓存、数据库副作用作自动补偿；
- 全局规则、模糊语义检索和独立规则管理产品面。

超出边界的请求必须在执行前明确降级、拆分或拒绝，不能由模型临场扩权。

## 3. 必过准入门槛

### Gate A：真实 L1 工程 Product Gate

在 `F:\dsh` 下建立独立、可丢弃、带 Git 基线的本地工程。使用真实 DSH 预设和真实模型完成一条至少跨两个模块的任务，必须观察到：

1. 模糊点先在原生对话中补问；不允许不明不白开始。
2. 第一道门禁只确认需求理解并放行只读方案，不写文件、不运行检查。
3. 只读方案落盘后，第二道门禁展示设计摘要、精确写入范围、冻结命令、验收标准和返工边界。
4. 实现角色只能读写允许前缀，不能运行 Shell 或自行验证。
5. 工程测试与代码审查在实现后并行，二者职责和可见上下文不同。
6. 黑盒验收不读取源码，只使用冻结命令及交付行为证据。
7. 至少执行一个正常通过样本；另用独立样本证明一次有证据的失败返回、同 ID 返工和完整下游复验。
8. 交付结论只引用当前版本证据；随后沉淀候选逐项决定，拒绝或修订不污染其他决定。

准入判定：所有硬标准通过、无越权工具调用、无伪造证据、无静默推进、Journal 可重放，且用户能明确判断“现在发生什么、下一步是什么、是否需要我操作”。

### Gate B：恢复与一致性矩阵

对以下切点逐一做可重复故障注入：

- 等待第一道或第二道门禁时重启；
- Agent 已分配但尚未报告时重启；
- 文件写入后、工程检查前重启；
- 并行测试/审查仅一方结束时重启；
- 返工后、复验前重启；
- 撤销意图已记录但文件事务未完成时中断；
- 沉淀部分候选已决定、单项待修订时重启。

每个切点必须证明：单 Host 写保护成立；不会把未知 Agent 显示为运行中；不会复用过期批准或过期验收；不会重复派发或重复提交；可恢复时从持久化边界继续，不可恢复时 fail-closed 并给出用户可执行的处理方式。

跨进程文件撤销事务若不能做到意图恢复，生产 v1 必须关闭该能力或明确降级为实验功能，不能以“正常路径测试通过”代替崩溃一致性。

### Gate C：运行时可靠性与资源上限

必须固定并验证：

- 每类 Agent、冻结命令和整轮运行的超时；
- 取消、停止、超时后的 lease 回收和孤儿状态判定；
- 最大并行 Agent 数、最大返工次数、最大事件/产物/检查点体积；
- 后台进程禁止规则及前台命令退出后的存活核对策略；
- DSH 进程退出、浏览器断线、模型失败、工具失败和磁盘错误的用户可见状态；
- Journal、原生 Session 和文件状态之间的一致性检查及诊断导出。

任何超过预算的行为都应进入明确终态或需处理状态，不能无限等待或静默重试。

由未参与实现的人在不阅读设计文档、不过度提示的情况下完成至少三类场景：需求补充、执行授权、失败返工。硬要求：

- 主要交流始终在 DSH 原生输入框；工作流页签没有第二套聊天输入；
- 首屏能区分当前阶段、最近发生的事实、下一步、是否需要用户操作；
- 跳过、并入、结束、失败、撤销和返工来源/次数/原因具有不同且一致的终态；
- 大型合同不塞入确认卡；确认卡只承载决定摘要，完整信息在“完整计划/证据”中可追溯；
- 用户不需要反复回答同一组评估问题。

五秒识别可作为观察指标，但不能用开发者陪同解释后的结果代替独立完成证据。

### Gate E：兼容、发布和回退

- 将 DSH `0.1.5-rc.1`、插件版本、构建产物摘要、Profile manifest 和最小数据库 schema 固定为一套发布基线；
- 全新 Profile 安装、既有 Profile 升级、旧 Journal 冷回放、插件停用/移除均通过；
- 每次 DSH 升级重新运行兼容矩阵，不默认继承上一版本结论；
- 提供安装、升级、回退、数据保留、已知边界和故障诊断文档；
- 发布包从干净源码构建，不依赖开发 Junction、未记录文件或本机绝对路径；
- 正式版本变更有 changelog，发布失败能回到上一可用插件版本且不破坏 Journal。

## 4. 执行顺序

### P0：冻结基线与修正文档（已完成）

- 修复沉淀确认卡“展示文本与保存文本标点不一致”；
- 增加精确文本保真回归；
- 把真实单项退回、原生输入修订、只重开该项的运行写入激活证据；
- 类型检查、构建、全量测试、官方 3080 安全重载和只读烟测。

完成条件：基线无已知语义偏差，代码、文档和在线实例指向同一版本。

### P1：真实 L1 工程准入（已完成，Gate A=`pass`）

- 建立独立 Git fixture 和冻结检查；
- 保留已完成的真实失败返回样本，另用干净 fixture 补齐正常通过样本；
- 记录门禁绑定、角色能力、文件摘要、命令证据、验收账本和用户体验观察；
- 只修阻断性问题，修复后从失效点重跑，不倒签原结果。
- 用新的干净 Git fixture 补做正常通过样本，启动前保存 `git status` 与基线提交证据，禁止继承前一取消 run 的受控写入；终态的 `deliverables` 必须覆盖全部本轮受控交付物，`retainedPriorRunArtifacts` 必须为空，验收只对该当前工作区状态作结论。

完成条件：Gate A 全部满足，形成可复放证据包。

### P2：恢复与可靠性（进行中）

- 根协调响应预算、只取消当前 turn、run 前后 Journal 恢复点和最多一次自动续接已有源码、自动化与真实证据；原生澄清等待豁免漏接已修复，通过 206 项回归和默认预算在线复验。子 Agent lease 独立预算与有界回收已补齐基础闭环；
- 冻结命令独立预算、人工处置及整轮请求／命令／时长均有在线样本，结束态角色提示已修正；下一步补活动中断矩阵，不能把 Agent 停止或人工处置当成任意 OS 进程树已清空；
- 自动化 Gate B/C 的故障注入；
- 优先补撤销事务意图日志、未知运行恢复、超时/取消/孤儿回收；
- 再处理后台进程存活核对和选择性复验；选择性复验不得削弱当前全量复验的安全性。

完成条件：故障矩阵无数据损坏、无越权续跑、无假终态。

### P3：独立体验与发布候选

- 执行 Gate D，不再由实现者逐项提示答案；
- 完成 Gate E 的干净安装、升级、回退和版本化；
- 冻结 RC，重复跑全量门禁后才决定是否标记生产 v1。

## 5. 判定规则

- 自动化测试通过只证明实现一致性，不自动证明真实模型质量或用户体验。
- 真实页面只读回放只证明展示和读取，不证明对应动作已真实执行。
- 经原生问答通道取得的决定证明“通过用户权限门禁”，不证明物理操作者身份；继续记录 `operator=unverified`。
- 每个结论必须附带可定位的 Session、revision、事件/记录版本和证据文件；没有证据的能力保持“未验证”。
- 任何安全、恢复或证据完整性的硬门槛失败，整体结论都是 `revise`，不能用多数通过抵消。

## 6. 版本标签

| 标签 | 条件 |
| --- | --- |
| 受控内部 Alpha | 当前：Gate A 已通过，根响应有界恢复已有源码、自动化和需求入口真实 Host 加速故障证据；其余恢复和发布准入未完成 |
| Limited Beta | Gate A 通过，正常路径有有界失败与明确恢复；Gate B/C 未全部关闭的问题逐项披露 |
| Release Candidate | Gate A-C 通过，Gate D/E 进入最终复核，无已知阻断项 |
| Production v1 | Gate A-E 全部通过，发布基线可安装、升级、回退且证据可重放 |

任意 DAG、L2/L3、OS 级网络/读取/进程隔离和全局规则产品化属于 v1 之后的独立路线，不作为拖延有限生产边界的前置条件，也不得被生产 v1 名称暗示为已支持。
