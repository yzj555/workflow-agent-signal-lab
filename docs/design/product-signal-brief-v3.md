# Product Signal Brief v3

> 冻结日期：2026-09-07  
> 状态：`COMPLETED / REVISE`  
> 证据范围：`personal-utility / builder-as-judge`  
> 目标裁决：`proceed / revise / stop`

## 1. 本轮只验证什么

v2 已裁决 `revise`。v3 只复验两项修订是否带来可感知收益：

1. 尚未创建 Journal Run 的需求澄清，也能在 Workflow View 中明确显示 `now / nextStep / attention`，同时明确标注“原生对话观察、尚未建立受控运行记录”，不伪造批准或执行。
2. 验证退回时，首屏直接显示退回原因、当前负责的返工任务、重新验收路径以及是否需要用户操作，不再只显示泛化的“实现中”。

首屏固定使用“现在／接下来／需要你”三行；交互仍只使用 DSH 原生输入框，Workflow View 没有输入控件。顺带检查讨论后不执行是否被正确画成终止而非待授权或后台继续，但这不追认 v2 中被协议污染的 S3。

## 2. 固定方法与门槛

三个场景均为官方 DSH 页面中的确定性只读回放，显著标记 `SIMULATION / 非真实运行`。不得创建正式 Run、调用模型、提交批准、执行业务动作或改写既有 Journal。Chat-only 与 Workflow View 必须使用相同事实。

场景顺序固定为 S1 → S2 → S3；视图顺序固定为 S1 Chat-first、S2 Workflow-first、S3 Chat-first。每次只展示当前规定视图，用户用自己的话回答：现在做什么、下一步是什么、是否需要自己操作、是否在五秒内看懂。输入回答的时间不计入五秒。看过对照后，再记录具体改善与相似任务复用意愿。

单场景通过要求：五秒内三项语义全部正确；`avoidableTurn=0`；用户能指出一个具体改善并明确愿意复用。至少 `2/3` 通过，且没有把普通讨论画成已启动任务，才是 `proceed`；三个有效场景不足两个通过则 `revise`；任何真实 Run、副作用、模型调用或批准立即 `stop`。

评估者不得在完成当前场景的两种视图及比较回答前透露标准答案、评价对错或提供解释。发生提示、截图错配、加载错误或其他协议污染时，该场景标记 `INVALID`，不采分；不得将被提示后的答案用于证明产品价值。

## 3. 冻结场景

### S1 · 需求仍含糊

- 用户表达：`帮我整理一份本季度供应商沟通摘要，给采购复盘会使用。`
- 已知：用途已知；供应商范围、沟通记录来源、覆盖日期和输出长度尚未明确。
- `now`：需求澄清，尚未开始整理。
- `nextStep`：用户补充关键范围，Agent 合并目标、边界和验收标准后再请用户确认。
- `attention`：需要用户回答。
- 反证：显示空白、误以为已经开始整理，或看不出现在需要用户补充。

### S2 · 验证退回返工

- 用户表达：`写一份会议室设备报障说明；必须包含报障入口、响应时限和紧急联系人，完成后独立验收。`
- 已知：初稿包含报障入口和响应时限，但缺少紧急联系人；独立 QA 已返回同一内容角色作一次范围内修正。
- `now`：验证已退回，内容 Agent 正在原范围内补充紧急联系人；“运行记录”不是实时心跳。
- `nextStep`：修正版交给独立 QA 重新逐条验收。
- `attention`：当前不需要用户操作。
- 反证：只识别“实现中”、看不出为何退回、把局部返工理解为整轮失败，或不知道后续仍会重新验收。

### S3 · 讨论后决定不执行

- 用户表达：`评估是否把客服录音样本交给外部质检服务；没有合规批准就不要上传。`
- 已知：缺少允许的录音范围和合规批准；本次结论是不执行。
- `now`：讨论已经结束，本模式没有建立受控运行。
- `nextStep`：没有自动下一步；条件具备后可在原生输入中重新提出。
- `attention`：当前不需要用户操作。
- 反证：把不执行画成失败、待授权或后台继续。

## 4. 预检与记录规则

正式观察使用第三组全新内容；此前 v3 工程预检使用的渠道伙伴、访客 Wi-Fi 与外部研究场景仅用于断言和人工视觉核对，不采用户分。正式图片生成后，评估者不得在用户首次观察前预览。

每场保存用户原话、五秒判断、三项逐项结果、`avoidableTurns`、对照回答、具体改善、复用意愿、裁决和理由。整轮保存有效场景数、通过数、协议异常、读写审计及最终 `decision`。`proceed` 只允许下一小步投入，不代表 Runtime、安全、H1—H3、Operational Product Gate 或市场价值通过。

## 5. 观察结果

最终裁决为 `revise`：

- S1 有效但失败。用户正确识别需求澄清、等待补充和需要自己操作，并明确指出 Workflow View 让“是否需要我操作”更直观；但五秒判断为“大概能行”，复用意愿为“应该会”，均未达到冻结的明确门槛。
- S2 有效但失败。用户正确识别返工实现、再次验证和不需要自己操作；但明确表示返工来源、次数和原因“完全没看出来”。“直观度”和“还可以”也不足以证明具体判断改善与明确复用意愿。
- S3 在 Chat-first 展示后，用户反馈“emmm，能不能别一直让我回答这几个问题了”。评估立即停止，S3 不采分；该反馈记录为评估方式本身造成的负担，不能转嫁为用户理解问题。

两个有效场景均失败，已经不可能达到 `2/3`，因此无需继续追问。安全审计保持为 0 模型调用、0 批准、0 业务写入，既有 Journal 与交付物不变。

下一轮不应继续使用逐场重复四问的形式。若再次验证，应在真实使用中仅在自然节点提出一次开放式问题，或采用不打断用户的观察记录；这属于评估方法修订，不代表当前产品已经通过。
