# 整轮预算：真实进程隔离矩阵

日期：2026-09-17。结论：本组隔离机制验证通过，生产准入仍为内部 Alpha。没有新增运行时功能或改动 DSH 核心。

## 验证对象与结果

| 场景 | 核对的事实 | 结果 |
| --- | --- | --- |
| 命令上限 1，尝试两条冻结检查 | 第一条真实进程完成；第二条没有 `command/started`，也没有进程自记的启动标记；账户封闭，业务 outcome 仍为空 | 通过 |
| 命令上限 2，恰好执行两条 | 工程测试与黑盒验收各执行一次；两次官方托管范围退出确认；正常交付 PASS，未误报额度耗尽 | 通过 |
| 累计有效时长 5000ms，运行中耗尽 | 上限小于命令独立 15000ms 超时；真实命令及受控后代已运行，再由 `run-budget` 中断；官方退出确认和只读 PID 消失核对一致 | 通过 |
| 根协调等待用户 | 没有后台角色时实际等待 5250ms，计时完全不变；随后保持同一原生问题等待并启动后台命令，仍计时到限 | 通过（时长场景内） |
| 回收范围与业务语义 | 独立对照进程仍存活；运行中断未生成业务 FAIL／自动 CANCELLED、未自动重试或撤销实现文件 | 通过（时长场景内） |

三项独立测试已连续通过两轮专项及一次全量；全量 321/321，未跳过。最终全量时长样本观测 5000ms，未结算预留与重启保守计入均为 0；回调延迟 6ms。三个最终矩阵采样的延迟分别为 0／12／6ms，不是毫秒级 OS 强杀精度承诺。

## 证据边界

- 使用当前本地官方 DSH 0.1.5-rc.1 的 AgentLoop、ToolRuntime、Questions、子 Agent 生命周期、PowerShell 和 local subprocess，真实单调时钟及临时 SQLite。
- 模型为脚本化适配器，门禁在夹具中回答；不经过 3080 Web，也不消耗业务模型。文件工具仍使用既有测试适配器实际写入临时文件，不证明 OS 文件隔离。
- 测试显式采用临时上下文的 `danger-full-access` 策略；官方 provider 仍负责托管进程。没有改变线上沙箱，也不把本组结果宣传为受限令牌或任意逃逸进程树的安全证明。
- 命令及受控后代各有 20 秒自退出保险；无关对照进程也有 20 秒保险，并由测试仅针对自己持有的 ChildProcess 句柄清理。
- 生产 `src/`、`lib/`、默认配置、writer 身份及 18 条 Journal 原始值逐项保持不变。本次没有重新构建／重载生产模块，没有开启线上预算、建立线上 Session 或批准真实门禁。

## 本次发现及处理

发现的是测试接线缺口，不是已确证的产品预算缺陷：原有原生命令预算集成用的是替身进程。接入真实 provider 时，测试策略缺少 `defaultMode` 导致工程角色被能力守卫拒绝；补全测试配置后才进入真实进程路径。另修正新增断言对 `CommandState.observation` 的读取位置。没有移除生产守卫、放宽权限或改预算语义；原失败记录保留。
