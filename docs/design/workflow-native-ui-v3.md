# Workflow Native UI v3 · 可判断状态修订

> 日期：2026-09-07  
> 实现状态：已构建并通过自动化／浏览器预检  
> 产品裁决状态：Product Signal v3 已裁决 `revise`

## 修订依据

Product Signal v2 的两个有效场景均失败：需求澄清时 Workflow View 为空；验证退回时用户只能识别“实现中”，无法快速识别退回原因和重新验收路径。该结果只支持修订呈现，不支持扩大 Runtime 或执行能力。

## 本次变化

- Workflow View 首屏固定显示“现在／接下来／需要你”，不再把 `nextStep` 藏在记录说明里。
- Journal 尚为空时，仅根据原生会话的运行、待处理交互和最后一条 Agent 说明形成“前运行投影”；来源明确写为“原生对话观察 · 尚未建立受控运行记录”，且始终不把对话文字当作 Signal Gate 批准。
- 前运行投影覆盖等待目标、分析中、等待补充、等待确认、需求轮次中断和讨论后不执行。没有运行时，后续阶段标为“未启动”，而不是完成或跳过。
- Host 的版本化只读快照新增可选 `latestReturn`。新 Host 从已提交的 `return/routed` 投影最近一次返回；旧快照缺少该字段仍可读取。
- 当前阶段仍位于返回目标阶段时，首屏显示返回来源、责任任务、尝试次数、真实退回原因以及重新验收路径；没有用户门禁时明确写“现在不需要你操作”。
- 前运行且没有 Agent 时不再显示“0 个 Agent”的空分工区域。

## 不变边界

- 没有新增聊天窗口、输入控件或面板内操作按钮；所有语义输入仍在 DSH 原生输入框。
- 没有修改 DSH 核心、审批、执行策略、Agent 权限或工作流事件。
- 原生会话观察不能证明进程存活，Journal 运行记录仍不冒充实时心跳。
- 本次没有实现项目文件／Shell 执行、多任务通用调度、程序 QA 或永久经验沉淀。

- 官方 DSH 3080 已重载为 PID 3264；RPC 已确认新 `latestReturn` 字段，stderr 为空。

## v3 裁决后的显著性修正

Product Signal v3 暴露的主要问题不是缺少返工字段，而是字段分散、视觉关系弱。后续修正将返工信息合并为一个连续判断单元：

- “现在”直接呈现“第几次返工 · 从哪一阶段退回 → 当前阶段”。
- 同一行下方连续呈现真实退回原因与当前责任任务，不再要求用户从摘要、阶段条和 Agent 列表之间拼接含义。
- “接下来”直接呈现责任任务完成后返回哪个阶段重新验收，并说明只重跑受影响的验收项。

后续工程路径说明：上述“只重跑受影响的验收项”仅描述当时的两节点文本闭环。`workflow-project-pilot/1` 当前采用更保守的完整下游复验，会重新运行工程测试与代码审查，再运行独立黑盒验收；只读投影已按合同类型分别显示，不再把两种策略混为一谈。详见 [原生受控工程闭环 v1](workflow-native-project-pilot-v1.md)。
- “需要你”继续独立显示；未触发门禁时明确写“现在不需要你操作”。

该修正已通过类型检查、构建与 98 项自动化测试。真实 DSH 3080 上的只读回放三个场景均无页面错误或受阻请求；0 模型调用、0 批准、0 业务写入，74 个原生会话、Journal 与既有产物保持不变。此次仅属于工程与视觉显著性核验，不改变 Product Signal v3 的 `revise` 裁决，也不再启动逐题问卷。
