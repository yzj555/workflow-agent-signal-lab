定位：`src/client/workflow-display.ts` 的角色呈现先处理 runtimeIssue，`stopped` 固定输出“已停止 · 需处理”；其后才处理运行 outcome。`src/host/workflow-controller.ts` 保存的是中断当时的历史原因，其“需要决定如何继续”不应在结束后被当成当前指令。这里是显示投影的责任，不应清除运行事实来美化界面。

修正遵循的边界：

- 对已经明确结束、退出核对为 stopped 的角色，显示“已停止 · 本轮已结束”一类终态；中断原因作为历史记录保留。
- 不把 unknown 或 stopping 因为全局结束标志而覆盖为安全停止；人工 ABANDONED 也不能抹掉旧 unknown。
- 已结束后，不再把旧补额／结束提示放在当前“需要操作”位置；完整原文仍可在审计记录查看。
- 处理通用状态规则，而不是改这两条记录、某张卡的文字或测试预期。
- 回归至少包括：活动阻塞 stopped、已结束 stopped、结束与 unknown 共存、stopping、PASS 正常角色、旧协议快照；原生宽／窄窗口检查不得引入第二个输入框。

不要求改变预算账本、恢复审批、角色权限或 schema；优先做小范围显示修正，再讨论剩余 Gate C 故障矩阵。

已落实：仅“整轮已结束 + 该角色 stopped”转为“已停止 · 本轮已结束”。旧 reason／lastSummary 收入原生“历史中断记录”折叠，默认不再呈现为当前动作；unknown/stopping 不降级，原文不改写。只修改显示投影和渲染两个源码文件。新增 8 项专项，旧代码 3 项失败、修后全量 329/329；真实 3080 的结束／unknown／PASS 四类样本、宽窄布局与键盘展开共 12 项通过。20 条 Journal、Host、配置和预设均不变，无重启、无新任务。详见 [修正核验](../../../.dsh/activation/workflow-agent-terminal-ui-20260917/verification.md)。
