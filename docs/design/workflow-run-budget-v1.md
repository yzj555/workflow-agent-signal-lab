一个正式 Run 共用一个资源账户，覆盖协调者与全部已派发子角色；串行、并行、同 ID 返工、自动恢复不另领一份额度。模型不能修改限额或清空用量。第三片新增可选有效时长，旧请求账户不补造时钟。

| 配置 | 实验默认值 | 含义 |
| --- | --- | --- |
| `runBudgetEnabled` | `false` | 仅在隔离测试显式开启；决定是否给新 Run 建账 |
| `runBudgetScope` | `[]` | 原生根 Session ID 精确名单；只给命中的新 Run 建账。全量须显式 `all` |

240／40／30 分钟都是可调整的 Alpha 防失控上限，不是性能、费用或用户体验实测所得的生产阈值。本轮未修改活动 Profile 或 preset 配置。

新 Run 须同时满足总开关开启和 scope 命中；此前仅写 `runBudgetEnabled: true` 的离线配置现在不会全量开户，保留旧测试意图须显式写 `runBudgetScope: all`。限额在 `run/created` 同一次持久化提交中冻结；同一草案修改、返工、失败、取消与冷打开不会归零。关闭 Host 开关、改变名单或调大配置只影响以后新 Run，已有账户仍按持久化限额检查。没有旧账户的历史 Run 不迁移、不补造消耗，也不宣称已被这套新预算覆盖。

## 记账与并发

`WorkflowJournalRecord` 新增可选 `budgets`，仍与完整领域事件保存在同一个根 Session 的 SQLite 原子行中。

- `revision` 仍等于领域事件数，决定合同和门禁版本。
- `budgets.revision` 单独递增，等于开户、执行／控制准入、每次超额封闭、原生恢复申请／结算、新用户消息恢复和计时修订的计数总和；计数、限额、run 归属在冷读时严格校验。审批审计和计时都在本行中，结束时与领域终态一起原子提交。
- `consumeRunBudget` 与领域提交使用同一串行队列，避免并行角色争抢最后一个额度时超发或覆盖记账。
- 必须写入成功才允许请求继续；写入失败不调用模型／命令执行器。失败、取消以及“已记账但未真正发出”的请求不退款，记录的是保守准入占用，**不是实际完成次数或账单**。
- 单纯记账不改变合同 revision，因此不会让待确认卡、工作流工具中的 `expectedRevision` 意外过期。客户端同时检查两条 revision，并接收领域 revision 不变的预算更新。
- 继续沿用 10,000 领域事件／16 MiB 单行上限。预算并未解决大聚合行的写入成本；性能验证仍待补。

请求次数首次试图超额时，或有效时长达到上限时，持久化 `blocked`，此后整个账户封闭。最后一个已预记账请求名额本身可以执行；限额不是一次额外的执行授权。时长使用短区间持久化预留，正常结算释放未使用部分；冷恢复把未结算预留单独记为保守用时，不把 Host 停机时间计入。

## 官方接线与退出语义

模型准入在预设的官方 `llm/stream` 中间件中等待记账，然后才调用 `next()`。使用官方 `isAgentLoopRequest` 标记、冻结请求、原生 sessionId 与当前已绑定的精确 Agent 实例联合校验；不从聊天文字推断身份，也不修改冻结的模型输入。Cordis 的 listener `this.ctx` 会受注册作用域影响，不能把它当作派发主体，因此不能用于父／子归属判断。回归已覆盖父中间件不重复扣子角色次数。

命令准入位于冻结合同校验之后、`command/started` 和 subprocess 派发之前。超额请求不会生成虚假的“命令已开始”事实。

耗尽时，控制层封闭新执行、取消当前协调响应并撤销本 Run 的活动子角色凭据；沿用现有有界 drain、命令退出和未提交写入补偿核对。回收证据明确区分 `stopping`、`stopped`、`unknown`；不生成业务 FAIL、PASS 或自动 CANCELLED，不自动重试，不消耗一次返工次数，不自动撤销工作区文件。

只读工作流视图区分“预算耗尽／时长预算耗尽”，显示模型与命令次数；有时钟的账户另显示已观测、重启保守计入、预留及回调延迟。保留各 Agent 的回收结果，不覆盖成“所有进程均已退出”。原有人工结束记录继续优先显示。
