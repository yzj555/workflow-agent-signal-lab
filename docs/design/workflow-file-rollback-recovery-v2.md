# 文件撤销中断恢复 v2

实现与隔离验证日期：2026-09-17。当前状态（2026-09-20）：已经授权空闲激活至本机 3080，12 项真实页面只读验收通过；本次没有执行真实撤销，完整生产准入仍未通过。见 [激活摘要](../validation/2026-09-20-activation.md)。沿用 DSH `0.1.5-rc.1` 的原生工具、用户问答和插件持久化，不修改上游核心或另建聊天界面。

## 解决什么

v1 的恢复进度只在内存中，文件改名／恢复后、`rollback/applied` 落盘前强退会留下无法可靠解释的现场。v2 用持久化撤销意图封闭这一窗口，不宣称文件系统与数据库之间有跨资源原子事务。

| 持久状态 | 重启后的行为 | 用户看到什么 |
| --- | --- | --- |
| 没有 `rollback/prepared` | 新协议未取得文件修改权 | 仍须正常预览、确认 |
| `prepared`／`interrupted` | 只读核对，保留文件和备份；不自动继续、不补写成功 | 撤销未完成；要求处置 |
| `applied` | 完成记录已有依据；仅核对清理对应备份，不重复恢复目标文件 | 已撤销 · 待清理 |
| `cleaned` | 无需再次清理或改写 Journal | 已撤销；原交付仅作历史 |

`prepared` 是授权／意图，不是完成证明；即使所有文件碰巧等于目标内容，也不能在启动时自动批准并记作撤销成功。

## 事务顺序

1. 仅终态、退出情况符合原规则的工程运行可撤销；核对最新检查点及同工作区其他执行。
2. 原生预览和用户确认。Host 在**同次 Journal 提交**中记录 `gate/decided` 和 `rollback/prepared`，然后才可修改工作区。
3. 用不可变检查点验证全部目标字节；暂存文件以独占创建并 sync。每个文件的备份／暂存路径由 Host UUID 和规范相对路径摘要确定，不能由模型或工作区清单指定。
4. 重新核对全体文件，逐项把当前文件改名留存；使用同目录硬链接独占安装目标文件。目标位置若出现新文件，安装报错而不覆盖。
5. 核对所有目标内容后提交 `rollback/applied`。提交失败不再无记录地“撤销撤销”，而是保留可识别现场，记为中断；若连中断状态也写不进去，已落盘的 prepared 仍阻止误报完成。
6. 只清理本事务且摘要匹配的备份和暂存文件，最后记录 `rollback/cleaned`。任一备份异常先整体拒绝清理，保留证据；已清理一部分后重启也可安全继续。

## 继续与冲突

仍使用原生输入框，用户可以说“核对并继续上次中断的文件撤销”。`workflow_rollback` 先核对同一事务，再生成新原生问题。卡片列出未开始、原文件已在备份中、已达到目标三类，不重复执行已恢复项。

- 新问题绑定当前 Journal 版本；旧问题 ID、拒绝或取消均不能放行。中断后必须新确认，不能沿用之前的答案。
- 任一当前文件、备份、暂存、检查点摘要异常或路径重定向时，停止并保留现场。新建同工作区／嵌套工作区会话不能绕过未完成事务。
- 已提交 applied 的事务重试只做原批准范围内的备份清理，不再次询问文件恢复，也不碰当前目标内容。后续原子替换的用户文件会保留；原地修改硬链接目标可能同时改变暂存摘要，此时拒绝清理，交由人工核对。
- 挂起时 `workflow_status` 不返回当前交付文件或自动沉淀来源，顶部和交付阶段不显示普通“通过”。原始 PASS 事件保留为历史事实，不改写测试证据。
- 派发与撤销临界段在 Host 内互斥；模型执行、后台角色和等待用户不因这一锁被串行化。

人工处理冲突时，先停止相关写入、备份当前内容，再逐项比较目标／备份／检查点。需要保留的用户修改移到另一个明确位置后才能重新核对。不要删除全部 `.workflow-rollback-*` 文件、手工伪造完成记录、删 writer 锁或覆盖数据库；插件不会自动决定丢弃哪一份。

## 兼容与边界

- 20 条旧 Journal 在新旧构建下投影一致；旧的只有 `rollback/applied` 的记录继续可读，没有批量迁移。
- 新增 `rollback/prepared`、`rollback/interrupted`、`rollback/cleaned` 事件。**第一次产生新协议记录后，不可直接降级到旧解析器。** 旧版会拒绝未知事件，这是 fail-closed，不是可用的回退路线；应保留支持此协议的读取／恢复版本。绝不为了降级恢复旧数据库而丢弃新记录。
- 本轮不自动接管 v1 遗留的、没有持久化意图的随机临时备份，也不推断其所有权；需人工核对。
- 保持 16 MiB／文件、100 文件／检查点和 64 MiB 修改前镜像边界；只管受控 write/edit 的普通文件内容。不恢复 ACL、时间戳、空目录、数据库、网络、进程或其他副作用。
- 测试为本机 Windows 文件系统上的进程中断，不是断电／磁盘控制器故障证明。硬链接不受支持或权限不足时保留现场并停止，不降级为可覆盖写入。
- 这不是对抗本地恶意进程的文件系统沙箱。其他编辑器、构建器等必须暂停对同一文件的并发写入；摘要检查与原子操作之间仍存在 OS 级竞争窗口，竞争修改可能被保留在改名后的备份中，需要人工检查。
- v1 写工具“观察失败后自动补偿”的独立路径仍使用旧内部恢复方法，本组不把它冒充完整跨资源事务。半写入会保留 unknown 和原始检查点，仍需人工核对。
- writer 锁沿用原规则，不因恢复能力自动抢锁；模型和命令预算配置未改变。
