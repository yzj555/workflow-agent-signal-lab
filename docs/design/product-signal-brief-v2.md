# Product Signal Brief v2

> 冻结日期：2026-09-07  
> 状态：`COMPLETED / REVISE`  
> 证据范围：`personal-utility / builder-as-judge`  
> 目标裁决：`proceed / revise / stop`

## 1. 目的与边界

本轮只判断：**DSH 原生对话作为主要交互时，只读 Workflow View 是否帮助用户在五秒内判断 `now / nextStep / attention`，并改善一次具体决策。**

这是工程样机存在后的前瞻检查，不能倒签成 0A 前已通过，也不计入 Operational Product Gate。三个场景均为官方 DSH 界面中的确定性只读回放，显著标记 `SIMULATION / 非真实运行`；不得创建正式 Run、调用模型、提交批准、执行动作或改写 Journal。Chat-only 与 Workflow View 使用完全相同的事实。

## 2. 固定方法与门槛

场景顺序固定为 S1 → S2 → S3；视图顺序固定为 S1 Chat-first、S2 Workflow-first、S3 Chat-first。Workflow 投影稳定后，用户回答“现在做什么、下一步是什么、是否需要我”。记录用户形成判断是否不超过五秒、原始回答、逐项语义判定、仅因表达不清导致的额外轮次，以及看过对照后是否能指出一个具体改善并愿意在相似任务中使用。

单场景通过要求：五秒内三项全部正确；`avoidableTurn=0`；用户能指出一个具体改善并愿意复用。至少 `2/3` 通过且没有把普通讨论画成已启动任务，才是 `proceed`；三个有效场景不足两个通过则 `revise`；任何正式 Run、副作用、模型调用或批准立即 `stop`。基础设施无效不计分，修复必须更换 Brief 版本或在首次用户观察前留下预检记录。

## 3. 冻结场景

### S1 · 需求仍含糊

- 用户表达：`帮我准备一份下周客户回访摘要，方便产品例会讨论。`
- 已知：用途已知；客户范围、访谈来源、时间边界和篇幅尚未明确。
- `now`：需求澄清，尚未开始生成。
- `nextStep`：用户补充关键范围，Agent 再合并需求供确认。
- `attention`：需要用户回答。
- 反证：误以为任务已启动，或不知道现在需要谁提供什么。

### S2 · 验证失败后返回

- 用户表达：`写一份新员工账号开通指引；必须包含申请入口、审批人和预计时长，完成后独立验收。`
- 已知：初稿包含申请入口和审批人，但缺少预计时长；独立 QA 已返回同一内容角色作一次范围内修正。
- `now`：返工进入实现阶段，日志记录内容 Agent 已重新派发；不是实时心跳声明。
- `nextStep`：修正版交给独立 QA 重新逐条验收。
- `attention`：当前不需要用户操作。
- 反证：把局部返工理解成整轮失败，或不知道后续仍有重新验收。

### S3 · 讨论后决定不执行

- 用户表达：`评估是否把月度运营报告同步给外部合作方；没有数据外发许可就不要发送。`
- 已知：缺少允许的数据范围和外发许可；用户决定本次不执行。
- `now`：评估已经结束，并决定不执行。
- `nextStep`：没有自动下一步；条件具备后可在原生输入中重新提出。
- `attention`：当前不需要用户操作。
- 反证：把不执行画成失败、待授权或后台继续。

## 4. 记录字段

每场保存：`scenarioId`、视图顺序、开始时间、投影摘要、标准答案、用户原话、五秒判断、逐项结果、`avoidableTurns`、对照摘要、具体改善、复用意愿和裁决理由。整轮保存有效场景数、通过数、错误／写请求审计及最终 `decision`。`proceed` 只允许下一小步投入，不代表 Runtime、安全、H1—H3 或市场价值通过。

## 5. 观察结果（2026-09-07）

最终裁决为 `revise`，不是 `proceed`：

- S1 有效但失败。需求澄清期间 Workflow View 没有形成可判断的投影；用户原话为“里面什么都没有，让我看什么”，之后也表示“没有很明显的一个体会感受”。
- S2 有效但失败。用户明确指出工作流视图的阶段信息一目了然，但无法确认五秒内看懂，并且只识别“实现中”，没有识别“验证失败后返回实现”的返工语义；复用意愿为“可能会吧”。
- S3 的 Chat-first 基线回答已记录，但评估者在展示 Workflow 对照前泄露了标准答案，构成协议污染，因此整场标记 `INVALID`、不采分，也不以被提示后的回答证明产品价值。

两个有效场景均未通过；即使 S3 重新测试并通过，整轮最多也只有 `1/3`，不可能达到 `proceed` 所需的 `2/3`，因此无需为了改变本轮裁决而继续消耗用户观察。审计仍为 0 模型调用、0 批准、0 业务写入，既有 Journal 与交付物未变化。原始结构化记录见 `.dsh/evidence/product-signal-v2/observations.json`。
