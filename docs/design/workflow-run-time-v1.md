## 计时口径

计量单位是当前正式 Run 内，至少一个已准入协调者或子角色正在工作的**区间并集**。它不是所有 Agent 时长之和，也不是从发出需求到最终交付的日历时长。

| 场景 | 怎么计 |
| --- | --- |
| 协调者模型响应与同一 turn 的控制工作 | 从持久化准入开始，至原生 turn 结束／等待用户 |
| 子角色派发、模型、工具、报告后等待退出 | 从持久化准入开始，至原生结算或可信 drain；报告不提前停止计时 |
| 根与多个子角色并行 | 重叠区间仅一次，不按角色数量倍增 |
| 只有协调者等原生问题，后台没有工作 | 暂停；回答后在下一次模型请求前重新持久化准入 |
| 根在等用户，但任一子角色仍工作 | 继续计时 |
| 返工、同 ID 再派发、同一需求草案改版 | 同一 Run 累计，不重置额度 |
| 预算封闭后的核对对话 | 不占执行时长；用原有有限控制请求池，不能执行工作流 |
| Host 停机 | 不累计停机时间；只处理旧 Host 未结算的短预留 |

正式 Run 尚未建立的需求入口、辅助标题／压缩模型请求不在这个账户内。时长到限立即撤权并请求取消；后续清理及未知进程不被虚报为已停止，也不以本时钟估算其实际资源费用。

## 开关和上限

`runBudgetEnabled` 与 `runTimeBudgetEnabled` 必须同时显式为 `true`，并且原生根会话命中 `runBudgetScope`，才为**新 Run**建立时长账户。两开关默认 `false`，scope 缺省为空名单，未改变活动配置。只有显式 `runBudgetScope: all` 才为所有符合原预设／根身份条件的新 Run 建账。已有计时账户移出名单仍按原限额监管，不回填其他旧运行。

`runActiveMs` 默认 1,800,000（30 分钟），有效整数范围 1～86,400,000 毫秒；极小值仅用于加速测试。30 分钟是待校准的 Alpha 上限，不是生产建议。限额与开户同一原子提交；改大 Host 默认值、关闭开关或重启不改变已有 Run 的冻结上限。旧 Run 不回填时长。

时长到限持久化 `blocked.resource=active-time`，复用 [原生恢复门禁](workflow-budget-recovery-v1.md)。原生命令固定补额对计时账户提出 +10 分钟；工具可提出最高 +30 分钟的有界追加。可只补时长，原用量和原因保留；三次批准上限、独立原生确认、等待下一条用户消息、禁止复活中断角色等边界不变。

## 持久化与重启

每个 `budgets.accounts[].time` 保存：

- `observedMs`：本 Host 已观测并持久化的有效毫秒；使用单调时钟，不做墙钟相减。
- `reservedMs`／`ownerId`：已落盘、尚未结算的短区间及其 Host 时钟实例。
- `uncertainMs`：冷恢复把旧 Host 未结算预留保守计入，单独标示，**不是精确测得耗时**。
- `overrunMs`：已观测到的终端计时回调延迟，不伪装成“毫秒级精确强杀”。
- `revision`：时长修订计数，纳入预算版本，不增加领域 revision，不使确认卡失效。

先持久化最多 5 秒预留，成功后才允许执行；剩余约 2.5 秒时续期。总未结算预留受 10 秒硬界限约束（正常续期约 7.5 秒以内）。正常暂停／停止按实观测结算并释放未使用预留；这不等于退还已消费额度。账户显示已记账量 `observedMs + uncertainMs`，预留另列，不能把预留显示为已耗时。

冷恢复在开启新准入前，把原先未结算的预留一次性转入 `uncertainMs`，清除旧 owner；再次冷打开不重复扣。旧 Agent 与命令的未知退出仍由既有 orphan 恢复协议处理，计时恢复不提供进程退出证明。

所有变化使用原有 Session 串行队列和 SQLite 原子行；冷读检查字段配对、余额、冻结限额、预算修订、补额链条与 owner。新严格字段只向前兼容新读取器：**一旦在线建了时长账户，不能只换回旧 JS 就声称完成数据回滚**。

## 到限、故障与精度

到限先封闭本 Run 的内存准入、取消协调者、撤销精确子角色凭据，再结算持久化；继续沿用有界 drain、冻结命令退出核对和写入补偿。保留验收、产物、返工原因；不生成虚假的 FAIL／PASS／CANCELLED。

续期等待落盘期间，旧预留的独立边界仍有效。若已用完旧凭据、续期仍未得到确认，按**存储安全故障**封闭 Journal 并取消当前受管执行，要求重新打开存储核实，不能误报预算耗尽。不能观测／持久化的事实不补造。卸载时最终时长结算与子角色回收一起受退出宽限约束，未确认则不声称可安全释放 writer。

Node 事件循环与 OS 调度不是实时系统：冻结／长阻塞后可能迟于额度边界才观察到终止。能观测的终端超时记入 `overrunMs`；凭据间隔内发生的时钟／持久化不确定性走故障阻塞。不保证任意逃逸 OS 子进程在额度点停止。默认关闭期间，原根无进展、子 lease、命令预算保持各自原行为。
