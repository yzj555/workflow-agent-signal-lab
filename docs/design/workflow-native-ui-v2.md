# 原生界面融合调整 v2

日期：2026-09-03。本次调整插件展示及其只读快照元数据，不修改业务事件协议、权限、门禁或 DSH 核心。

## 展示决定

- 移除 `conversation.input.dock` 中整块独立状态卡，不再在原生输入框上方重复占位。
- 移除自制 `document.body` 浮层、独立品牌头、渐变、发光圆点和持续呼吸动画。
- 将只读工作流登记到官方 `conversation.view`，与原生「对话／轨迹」并列。标签切换、滚动区域、输入框与问答仍由 DSH 管理。
- 依据官方 `ctx.sessions.list` 的当前会话及明确预设 ID 决定是否登记页签；切换到其他模式就撤回，只登记一次。不根据用户文本启用模式。
- 顶部只在已有记录或读取异常时保留简短状态；空白／读取初始态不再显示长期占位提示。空白会话沿用 DSH 自己的 Hero 与输入框；原生会话页头出现后才展示页签。
- 界面使用官方 `DisclosureRow`、`StateDot` 和图标，沿用 `--dsw-*` 主题变量以及原生会话内容宽度。主要正文为 13–14px，细节可展开。
- 宽窗口显示横向阶段关系，窄容器转为纵向；阶段说明、记录来源按需展开。未记录阶段不推测为完成，持久化 running 不显示为实时心跳；有条件通过不显示为绿色 PASS。

官方 `details` 是已经被工具详情占用的单席位，因此本次使用可追加的原生视图，不覆盖工具详情，也不重造对话外壳。代价是详细流程与聊天正文通过原生页签切换；输入框始终保留。

## 阶段与整轮结束标识（2026-09-03 后续）

用户指出：缺少执行步骤仍留着空心序号、已结束的交付仍为蓝色，无法判断是否漏跑。本次在每个阶段下直接显示文字状态，并在阶段条上方显示整轮结束结论；悬停或展开「各阶段做什么」可查看对应依据。

当前真实文本运行显示如下，不把不同原因一概写成“跳过”：

| 阶段 | 标识 | 依据 |
|---|---|---|
| 需求确认 | 已确认 | 当前门禁已有有效批准 |
| 计划与拆解 | 并入需求确认 | 固定的内容→独立验收计划随需求合同确认，不另设执行阶段 |
| 实现 | 已完成 | 当前内容任务完成 |
| 验证 | 已完成 | 独立 QA 已完成当前文本的逐条验收 |
| 独立审查 | 本次无需 | 此文本合同不额外安排审查；不表示省略独立 QA |
| 交付 | 已交付 | PASS 已保存，任务和验收记录一致；不再标为当前阶段 |
| 沉淀 | 尚未接入 | 当前文本闭环未实现该能力，不冒充完成或用户跳过 |

当前事件协议没有显式的阶段跳过记录，本次也没有新增“跳过”按钮、授权或执行能力。普通／历史运行没有有效完成依据时，结束后显示「未执行」，不推断它获准跳过。取消、失败、有条件交付与成功交付分别显示；过期、未完成任务和仍为 running 的记录不因整轮结束而变绿。交付后如有未决定的沉淀建议，仍保留「待你决定」，不自动采纳。

实现仅新增只读 `run.executionProfile?: 'workflow-text-pilot/1'`：Host 核对持久合同的版本、权限边界、角色和串行关系后投影，不从标题、当前预设选择或聊天内容猜测路径。新客户端兼容字段缺失，按未知路径保守展示；未知字段值仍拒绝。旧客户端采用严格快照校验，因此本次 Host 与客户端配套更新，旧页面需要刷新；不声称新 Host 可与任意旧客户端混用。没有修改 Journal schema、事件、任务或批准记录。
