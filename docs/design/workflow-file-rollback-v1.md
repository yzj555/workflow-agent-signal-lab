# 工作区文件撤销 v1

2026-09-17 后续：新增 [v2 中断恢复协议](workflow-file-rollback-recovery-v2.md)，目前为已验证的候选，尚未替换 3080 的 v1 撤销实现。下文保留 v1 的历史行为与当时限制；v2 不再在 Journal 完成提交失败后做无记录补偿，而是保留事务并要求重新核对确认。

状态（2026-09-07）：源码实现并重载到官方 3080；类型检查、构建、110 项离线回归和 10 组真实原生页面只读布局核验通过。本能力属于 `workflow-project-pilot/1`，不改变 L0 文本路径。

## 1. 语义边界

“自动撤销”指 **系统自动完成用户明确批准的文件恢复操作**，不指 Agent 自行判断何时回退。

- `workflow_stop`：收回执行权并停止受控 Agent，不改文件。
- `workflow_return`：保留当前变更，带失败证据返回同一实现 Agent 返工。
- `workflow_rollback`：只在用户明确要求时使用；活动运行必须先停止，再展示精确文件预览并通过原生用户门禁确认。

失败、测试未通过或模型判断均不会静默触发撤销。

## 2. 检查点如何形成

实现 Agent 的 `write`／`edit` 经 DSH 正式 `tools/execute` 执行缝接入：

1. 工具体运行前，Host 再次校验角色、工作区和写入前缀。
2. 某文件在当前实现任务版本中第一次被写入前，Host 读取其原始字节；不存在则记录 `absent`。
3. 已有文件内容按 SHA-256 存入插件拥有的 `workspace-checkpoints` 内容寻址目录。
4. `checkpoint/file-captured` 成功写入 Journal 后，工具体才可运行。
5. 工具体结束后，无论返回成功还是失败，Host 都读取当前摘要并以 `checkpoint/file-observed` 做 CAS 更新。
6. 同一文件的并发写入按根会话和规范绝对路径串行；若文件在受控写入之外发生变化，后续写入停止。

若工具已经改变文件，但结果无法写入 Journal，控制器会尝试恢复到该工具调用前的已记录状态；恢复也失败时明确报告需要人工核对，不伪装成一致。

当前上限：单文件 16 MiB；单个实现检查点最多 100 个文件；原始已有内容合计最多 64 MiB。无法在上限内可靠留底时，写入在工具体运行前被拒绝。

## 3. 用户撤销流程

```text
用户在原生输入框明确要求撤销
        │
        ├─ 运行仍活动 ─→ workflow_stop（只停止，不改文件）
        │
        └─ 运行已结束 ─→ 选择最新未撤销检查点
                           │
                           ├─ 当前摘要 ≠ Agent 最后记录 ─→ 冲突，整体拒绝
                           │
                           └─ 展示“恢复已有文件／删除本轮新增文件”清单
                                      │
                                      ├─ 用户保留当前文件 ─→ 不执行
                                      │
                                      └─ 用户原生确认撤销
                                                 │
                                                 ├─ 文件恢复事务
                                                 ├─ Journal 记录 rollback/applied
                                                 └─ 只读面板标记“已撤销”
```

撤销采用后进先出：返工产生 `implementation@2` 时，必须先撤销它，之后才能在用户再次明确要求并确认后撤销 `implementation@1`。这使“撤销本次返工”和“撤销整轮实现”保持可区分。

## 4. 冲突与提交

- 预览前检查一次文件摘要；用户确认后、实际恢复前再次检查。
- 任一文件不再等于检查点记录的最终状态，则整个操作不开始，不强行覆盖用户或其他程序的修改。
- 多文件恢复先准备原内容，再将当前文件临时改名保留；若中途失败，按反向顺序补偿回恢复前状态。
- Journal 提交失败时也执行补偿。Journal 提交成功后才清理临时备份。
- 进程在文件替换与 Journal 提交之间被强制终止仍是 v1 的崩溃窗口；后续需增加可恢复的 rollback-intent 事务记录，当前不宣称跨进程崩溃原子性。

## 5. 明确不覆盖的内容

v1 只恢复受控 `write`／`edit` 触及的普通工作区文件内容：

- 不删除因此新建的空目录；
- 不恢复时间戳、ACL 或其他文件元数据；
- 不处理 Git 状态之外的远端提交、发布或外部消息；
- 不补偿测试脚本可能造成的网络、进程、缓存、数据库或设备副作用；
- 不把 `PASS` 历史改写掉，但撤销后不再把该交付物显示为当前有效结果。

工作流页会显示“已撤销”，并说明原验收结论只保留历史意义。

## 6. 关键实现位置

- `src/host/workflow-artifacts.ts`：二进制内容寻址检查点、安全路径读取和多文件恢复事务。
- `src/host/workflow-control.ts`：通过 DSH `tools/execute` 正式缝接入写入前后观察。
- `src/host/workflow-controller.ts`：检查点 CAS、撤销预览、原生门禁、冲突检查和 Journal／文件补偿。
- `src/workflow-events.ts`：`checkpoint/file-captured`、`checkpoint/file-observed`、`rollback/applied` 的严格重放。
- `src/workflow-run-projection.ts` 与 `src/client/*`：可撤销数量、最新撤销结果和“已撤销”阶段标识。

## 7. 已验证行为

- 新增文件在用户确认后被删除；
- 已有文件按修改前的精确字节恢复；
- 活动运行不能直接撤销；
- 外部编辑触发冲突且保持不变；
- 已通过交付的运行仍可撤销，但不再返回当前交付物；
- 官方原生 AgentLoop 的真实 `write` 调用会形成检查点；
- 旧快照可缺少 `rollback` 字段继续读取；
- 浏览器 bundle 不含 Node 内置模块；
- 官方 3080 实例中，“已撤销”同时显示为顶部终态、交付阶段标识和结束提示；
- 10 组宽／窄、浅／深色及关键运行状态的真实原生页面布局回归均无水平溢出、无页面错误、无插件输入框。

部署与布局证据保存在 `.dsh/evidence/workflow-file-rollback-activation-20260907`。布局核验使用只读演示快照，没有提交真实任务、代替用户批准或对业务文件执行撤销。

## 8. 撤销标识显著性调整（2026-09-08）

当前方案通过信息层级和节点形状同时满足辨识度与原生一致性：撤销后，结果区的主标题直接显示“已撤销”，沿用原有 18px／28px 标题规格；下一行显示恢复文件数量和历史结果说明，任务名称降为次要上下文。不再在“现在”一栏重复同一状态；原生页面的留白、细线、输入框与其余信息行保持原有结构。

用户随后澄清，主要问题是 DSH 会话页头中的“已撤销”不够明显。页头状态现在与工作流视图状态显式区分：仍留在原生 `conversation.session.header.actions` 插槽中，在 Agent 预设之后用 1px 原生分隔线划分；回退图标和文字使用主文字色，文字提升为 13px／600。它没有背景、外框或胶囊，因此仍是标题栏的一部分，不形成额外控件感。

交付阶段使用独立的 `rolled_back` 展示状态，以原尺寸的实心节点承载反色回退图标；“已撤销”文字加粗，其他已完成节点保留历史事实并淡化绿色。状态只使用当前原生主题的文字与背景颜色，不另设大面积底色、粗侧边或标签胶囊。

当用户正在确认下一次撤销时，顶部和交付阶段显示“待撤销确认”，结束提示区分上次已完成与本次待确认，不显示已完成撤销的大字状态。

本次改动限于结果区展示；构建、类型检查和 5 项原生 UI 回归通过，官方 3080 页面完成普通交付、撤销浅色宽屏、深色宽／窄屏和再次撤销待确认共 5 个只读场景验证。现有服务可直接读取更新后的客户端包，刷新页面即可加载，无需重启服务。

结果区层级截图与报告位于 `.dsh/evidence/workflow-rollback-result-hierarchy-20260908/layout`；页头状态修订后的宽屏浅色、宽屏深色和窄屏深色证据位于 `.dsh/evidence/workflow-rollback-header-balance-20260908/layout`。这些场景均为浏览器内注入的展示数据，不是新的真实任务或撤销记录。

先前的大面积强调版本因不融入被撤回，随后的小字信息行版本又削弱了辨识度；对应证据分别保留在 `.dsh/evidence/workflow-rollback-salience-20260908/layout` 和 `.dsh/evidence/workflow-rollback-native-fit-20260908/layout`。当前版本调整主次关系，保留已确认的原生交互方式；页面检查通过不代表用户已认可视觉效果。
