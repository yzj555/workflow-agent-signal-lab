# 关键工作切点：隔离冷恢复验证

日期：2026-09-17。这组只补验证，**未修改运行时源码、构建、默认配置或线上记录**。五项专项和全量结果见 [本轮核验](../../.dsh/activation/workflow-critical-recovery-20260917/verification.md)。

## 哪些行为已得到证据

| 中断切点 | 冷启动必须做到 | 明确推进后的要求 |
| --- | --- | --- |
| 文件已写入部分字节，工具尚未返回 | 保留原始字节检查点及现场；角色 unknown，不登记完成产物，不自动恢复或继续写 | 拒绝推进；先核实旧运行和文件，不能把文件存在当作写入成功 |
| 失败返工已登记，尚未开始重做 | 保留失败原因、任务新版本及第 1 次返工计数；旧验收为 PENDING；不开新角色 | 复用原实现 Agent，再跑工程测试、代码审查和黑盒验收，才能交付 |
| 全部验收完成，尚未声明交付 | 保留验收证据，outcome 仍为空；不自动宣布 PASS | 核对当前文件后仅交付一次，不重复模型调用或执行测试 |
| 上述切点之后文件又被外部修改 | 不覆盖外部修改，也不补造当前版本证据 | 摘要不匹配则拒绝交付，不能拿旧 PASS 代表新内容 |
| 一条规则已采纳，另一条已修订但尚未重新确认 | 已采纳规则保持生效，另一条待确认；不自动采纳，不重开已采纳项 | 旧问题 ID 拒绝；重新确认仅处理待定项，不增加重复修订或规则 |

每例均真实终止独立测试 Host，而不是仅销毁同进程 Controller。先验证旧 writer 标记阻止接管；持有旧进程句柄的测试控制者确认退出、验证唯一临时目录和 token 后，才归档旧标记。它不是生产自动抢锁或恢复命令。

每次冷恢复后再打开／关闭两个独立新 Host：Journal 原始行摘要、任务和规则状态保持不变，没有新模型请求、门禁或子 Agent 自动派发。返工、交付、沉淀的明确推进完成后，也再次核验重复冷启动。

## 如何避免测试掩盖问题

- 使用实际官方 AgentLoop、ToolRuntime、Questions、continuable subagent、SQLite、PowerShell 和 local subprocess；模型是脚本化适配器，Connection 为无监听测试适配器。
- 冻结检查真实运行 `node --test recovery-check.test.cjs`：首次返工样本公开导出为 false，检查真实失败；返工后为 true，工程与黑盒各重新执行一次。每次都有独立进程标记，不只相信角色报告。
- 文件切点由测试文件适配器实际写入前半字节并阻塞，随后强停 Host；写入前检查点、写入后记录及产物路径均走生产控制层。**这不是对官方文件写实现的任意 OS 指令切点注入**，也不声称部分文件会自动恢复。
- 不手工修改 Journal、不手工补交付或验收，不调用夹具提前 Session flush；沿用产品入口自身的持久化屏障。
- 明确推进通过测试 IPC 发起，原生问题由脚本化答案提供；该证据不是用户独立体验或真实业务模型质量验收。
- 旧失败不覆盖。首轮 4/5 中的一项失败是测试把原生工具的 `value.result` JSON 当成直接对象；只修正解析，并增加交付文件摘要断言，没有修改运行时或降低预期。

## 有限通过，不是整个 Gate B 完成

本组覆盖的是上述明确切点，不覆盖：

- SQLite 提交内部任意指令、OS 掉电和磁盘硬件故障；
- 文件撤销事务在改文件与提交记录之间中断；
- 第一／第二道需求与执行门禁的全部重启分支；
- 所有文件类型、长时间负载或默认阈值组合；
- 新环境安装、插件停用、实际失败回退与独立用户验收。

半写入现场的原始备份仍可校验，但这不等于已经完成文件恢复。遇到 unknown 必须先核实，使用版本控制或经过审阅的恢复操作；不能直接复用旧授权，也不应自动覆盖用户后来修改过的文件。

文件撤销继续是已知的跨进程风险边界，详见 [文件撤销协议](workflow-file-rollback-v1.md)。其正常路径通过不替代事务中断安全；在该项关闭或补齐前，不宣布完整基础生产准入。

## 复跑

本批次候选与保护基线已建立。未改变当前 Host／构建／记录时，可使用新标签执行：

```powershell
node scripts/critical-recovery-matrix.mjs test another-focused-label
node scripts/critical-recovery-matrix.mjs full another-regression-label
node scripts/critical-recovery-matrix.mjs check another-protection-label
```

以上脚本不重启 3080、不覆盖已有证据；Host 或记录已经变化时应建立新批次，不能绕过旧守卫继续运行。本组没有部署步骤，因为候选从空输出目录生成的 24 个文件与当前线上构建逐字节一致。
