## 新设备的第一步

先克隆仓库并阅读 [Production v1 准入计划](../design/workflow-production-readiness-v1.md)和[首次 Profile 配置顺序](workflow-profile-activation.md)。安装指定版本的 Node.js 和 pnpm；不以全局 `dsh` 的命令名代替实际 Host 版本和模块身份核验。

在源码根目录执行隔离发行构建。下例的证据父目录需自行选择并已存在，输出子目录必须是新目录，不要指向部署目录或覆盖旧证据：

```powershell
git clone https://github.com/yzj555/workflow-agent-signal-lab.git
Set-Location .\workflow-agent-signal-lab
node --version
pnpm --version
pnpm run release:build --output C:/work/evidence/workflow-rc12 --version 1.0.0-rc.12
```

发行器在仓库外按 frozen lock 安装依赖、检查类型、构建和测试，生成停用的候选包；不要求旧设备的 DSH 开发 Junction，也不启动 Host 或发布包。应核对结果及归档摘要，不把首次构建结果自动视作全部运行验收。源码发行输入必须保持原字节；`.gitattributes` 禁止 Git 自动转换换行，避免换机改变已冻结的输入摘要。正式版本参数仍被发行器拒绝，不能靠改版本号跳过准入。

不要直接执行历史 `activate-*`、`restart-*` 或在线测试脚本；部分脚本绑定旧设备的目录和会话。不要将旧设备保留的 `lib`、`node_modules` 或本机 `cordis.patch.yml` 当作当前候选部署。
