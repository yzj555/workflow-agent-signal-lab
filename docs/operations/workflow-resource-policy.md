## 配置与边界

机器可读候选为 [`src/workflow-resource-candidate.json`](../../src/workflow-resource-candidate.json)。它不被当前 Profile 自动加载，不含数据目录，不修改历史运行的冻结额度。测试将其与实际配置解析器及已有常量对照，避免文档数值与实现分离。

| 对象 | 候选限制 | 含义 |
| --- | --- | --- |
| 根响应 | 无进展 180 秒；单次恢复 120 秒；取消宽限 15 秒 | 不是整轮任务总时长；明确等待用户时按已有规则豁免 |
| 子角色 | 启动 30 秒、无进展 180 秒、单次最长 20 分钟；报告／取消各 15 秒 | 退出仍须取得证据，超时不自动等于已停止 |
| 冻结命令 | 执行 120 秒、退出核对宽限 15 秒 | 不允许自行改成后台命令；进程处置沿用既有规则 |
| 新受控运行 | 240 次模型准入、40 次命令准入、30 分钟有效活动时间 | 根／子活动计时取并集，不按角色数累加；计数不是 Token 或费用上限 |
| 补额和返工 | 最多 3 次明确补额；一次同范围返工 | 补额必须经原生门禁；停止后的旧执行不能因补额自动恢复 |
| 单轮工程角色图 | 最大并行宽度 2 | 仅描述已冻结角色图，**不是 Host 总并发上限** |
| Host 准入候选 | 2 个活动根范围／同时根模型流，4 个子角色范围 | 仅此预设；整批预留、取消中／未知退出占位、名额拒绝后不自动续跑；尚未在线启用 |
| 文件／检查点 | 单文件 16 MiB；单次实现检查点 100 文件／64 MiB | 已有候选容量守卫；不等于整个磁盘的配额 |
| Journal | 9000 事件／14 MiB 暂停新执行；10000 事件／16 MiB 硬限 | 预留空间用于收尾；不删历史、不虚构退出 |

上述值是对现有机制的显式候选组合，不是通过少量性能样本推导的最佳阈值。候选的 `runBudgetEnabled=true`、`runBudgetScope="all"` 已在明确选择 `packaged-candidate` 的隔离安装环境核验；它不会自动改变旧实验 Profile，正式环境也尚未创建。需求分析进入正式 run 之前、原生辅助模型调用尚不计入正式 run 的额度，不能宣称整个 DSH 已有总成本封顶。

Host 准入已经接入独立开发候选，语义见 [并发准入说明](../design/workflow-host-admission-v1.md)，同输入双轮 466/466 及取消／未知退出、原生组件接线的隔离结果见 [本批验收](../validation/2026-09-20-host-admission.md)。JSON 的 `hostConcurrency.enforced=true` 描述显式使用 `engineConfig` 时的候选行为，**不是当前 3080 已开启**；配置解析器仍默认关闭，上线须明确批准。上游其他工作流引擎的 `maxConcurrentAgents` 不约束本插件直接派发路径。

“活动根范围”是根模型流和未结束角色所涉及的会话并集，不是全部未完成任务。根流在迭代器结算后才释放；角色及关联未知命令依赖持久化事实。原生门禁明确人工结束属于用户处置，可放行新范围，但原 unknown 和未确认退出的证据不改写。

## 可重复离线测量

在**已经独立构建、且不供在线 Host 使用**的开发副本中运行；先按仓库开发说明准备匹配的官方依赖。该脚本不是安装包验证，也不启动 DSH、浏览器、真实模型或业务命令。

```powershell
# 输出目录必须是新的绝对路径；已存在时拒绝覆盖。
node scripts/benchmark-workflow.mjs --mode native --duration-ms 60000 --events 8500 --roots 2 --output C:/test-evidence/native-reference
node scripts/benchmark-workflow.mjs --mode workflow --duration-ms 60000 --events 8500 --roots 2 --output C:/test-evidence/workflow-reference
# 30 分钟实际墙钟持续记账，不使用加速时钟。
node scripts/benchmark-workflow.mjs --mode workflow --duration-ms 1800000 --events 8500 --roots 2 --output C:/test-evidence/workflow-soak
```

可选 `--history-bytes 13631488` 将每个合成根会话扩至 13 MiB。参数上界：4 根、8800 个偶数事件、每根 13 MiB、最长 30 分钟。相同机器的性能对照应串行运行，记录同时运行的其他工作；不要拿不同负载直接算提升比例。

脚本只在系统临时目录创建自己的数据，保留 SQLite／原生日志及结果供复核；不会自动清除这些证据。子进程有断开退出和有限时长保险，父进程仅能终止自己持有的子进程句柄，不按名称或端口找进程。输出包括 `receipt.json`、子进程日志和临时数据位置；回执仅在正常退出及正确性断言通过时为 `completed`。失败也保留回执，不覆盖旧样本。

### 负载与指标解释

- 工作流侧使用真实官方 SQLite 存储、Journal、只读快照处理器和有效时长记账器；每根模拟两个页面读取者及三个重叠活动标记。标记不是实际角色 Agent，两页读取也不是浏览器端到端测量。
- 每根每秒两次快照读取、每 10 秒一次模型准入记账、每 60 秒一次命令准入记账；同时包含记账器自己的定时预留／结算。没有发送模型请求或启动命令。
- 原生侧使用相同数量的合成事件及官方 JSONL 创建／关闭／冷开／读取／追加。它是持久化参照，**不是语义、数据布局、返回大小完全相同的工作流基线**；不能由此宣称插件端到端比原生快。
- 报告冷开、快照读取、显式记账写入、事件循环延迟、CPU 时间及采样内存。显式写入分位数不包含每次内部时长检查点；总 CPU／事件循环观察覆盖这些活动。短样本的 p95 可能就是最大值，不能当作已校准的长期 SLO。
- 持续运行核对事件 revision 未改变、请求／命令计数正确、活动时长未按并行人数重复累计、未伪造业务 PASS/FAIL；最后退出并重新打开存储，对照持久化完整快照。冷开检查不属于稳态延迟样本。
- 内存为定期采样峰值，不是 OS 强制配额；单机有限时长样本不能证明没有任何泄漏、磁盘故障或系统级卡顿。
