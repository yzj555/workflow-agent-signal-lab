## 进入真实项目时怎样使用

1. 使用独立工作副本或分支，保存可恢复的版本基线。不要直接指向线上部署目录、唯一数据副本或含生产凭据的环境。
2. 在 DSH 选择工作流 Agent 预设，在**原生输入框**描述目标。先补齐不明确的点；需求确认仅放行合同中说明的下一步，不代表整轮无限授权。
3. 执行授权时核对允许写入的路径、逐字冻结的命令、验收标准和返工范围。脚本能间接联网或修改外部资源时，插件的路径限制不能代替 OS 沙箱。
4. 通过“工作流”页签看阶段、角色、下一步和是否需要你操作。不需要逐步发“继续”；但新的授权、需求变化、异常处置必须明确决定。
5. 结束后审查本轮文件差异并自行提交版本；沉淀只采纳准确、有限定条件的规则。不要因为页面显示完成就直接部署到生产服务。

## 使用边界

| 可以纳入基础使用 | 暂不纳入 |
| --- | --- |
| L0 文本；L1 本地受控代码变更；固定角色及串并行路径；最多一次同范围返工 | 任意动态 DAG、无限返工、无人值守执行 |
| 人工审阅过的本地前台构建、检查和测试命令 | 发布、升权、安装、进程管理、外部网络／数据库／云资源写入 |
| 原生确认、已有证据的文件交付、逐项采纳规则 | 用模型承诺代替权限边界；把源码可见测试当成黑盒验收 |
| 精确停止状态及未知运行的审计处置 | 把 PID 消失、人工结束或 Agent idle 当成整个进程树已停止 |

累计请求／命令／时长预算仍默认关闭、scope 为空；本轮没有悄悄启用。单角色与单命令的现有超时仍有效。若新任务需要整轮资源上限，应先确定范围并显式启用验证，不能把当前默认行为描述成已有整轮硬上限。

文件撤销的跨进程恢复已形成候选，但当前 3080 仍未启用。即使激活后，也不要把它作为唯一恢复手段；保留版本控制基线。停止工作流不会自动恢复文件，也不能撤销脚本产生的外部副作用。v2 新协议首次写入后，不可直接降级旧解析器，见 [恢复与兼容边界](../design/workflow-file-rollback-recovery-v2.md)。

## 遇到异常

- **保存失败／超时，工作流尚未创建**：没有获得正式执行授权。先检查存储和会话服务，解决后重新提交；不手工补写 Journal。
- **正在停止**：等待托管范围回收；不要重复发起同一工作，也不要立即重启来隐藏状态。
- **未确认停止**：保留未知事实，核实旧运行影响；需要时走现有人工处置门禁。人工结束旧 run 不等于退出已证实，不能沿用旧授权继续。
- **writer 冲突／存储异常**：停止新工作，保留现场。不要删锁重试或覆盖数据库；核对进程创建时间、命令行及 owner，并先备份。
- **撤销未完成（v2 激活后）**：在原生输入框要求核对继续；每次恢复需新的确认。发现冲突时先保留用户当前内容、原始备份和 Journal，再人工比较，不能批量删除临时文件。
- **已撤销 · 待清理（v2 激活后）**：完成记录已有依据；可要求重试备份核对清理，不会重复恢复或覆盖目标文件。备份异常时保持挂起。
- **升级失败**：确认空闲且身份一致后回退已归档构建；保留当前数据。只有经过兼容检查的版本才能读取原记录，不能默认降级 schema。

本轮激活脚本是一次性、固定目标的维护程序，不是任意时间可重跑的恢复工具。下一次升级必须新建基线并重新取得需要的中断许可。

## 从当前版本到基础准入，接下来只做这些

1. **关键恢复剩余收口**：前五项切点已验证；文件撤销恢复已形成候选，下一步须新授权的空闲激活及只读验收，再补需求／执行门禁的剩余重启分支。不把有限切点通过当作完整崩溃一致性，也不重用之前已消耗的重启许可。
2. **完成本机发布与恢复基线**：本轮已有构建摘要、旧版保留、无迁移兼容和受控激活；仍需新的安装环境／Profile、停用及完整失败回退验收。当前开发 Junction 不等于可分发安装包。
3. **小范围真实任务试用**：先核对模型连通性，再挑一项可恢复的真实需求，检查实际模型、门禁、差异与交付，不再重复展示用的问卷。宿主目前保留原有 SOCKS 代理不支持、相关 scheme 直连的提示，本轮未改网络配置；需要核实这是否符合预期。自动化和只读页面回放不能代替真实任务证据。

高级能力不作为这三项的前置条件。完整五组准入要求保留在 [生产计划](../design/workflow-production-readiness-v1.md)，不因缩小试用范围而将未完成的 Gate 改成通过。
