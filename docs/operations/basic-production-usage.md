## 进入真实项目时怎样使用

1. 使用独立工作副本或分支，保存可恢复的版本基线。不要直接指向线上部署目录、唯一数据副本或含生产凭据的环境。
2. 在 DSH 选择工作流 Agent 预设，在**原生输入框**描述目标。先补齐不明确的点；需求确认仅放行合同中说明的下一步，不代表整轮无限授权。
3. 执行授权时核对允许写入的路径、逐字冻结的命令、验收标准和返工范围。脚本能间接联网或修改外部资源时，插件的路径限制不能代替 OS 沙箱。
4. 通过“工作流”页签看阶段、角色、下一步和是否需要你操作。不需要逐步发“继续”；但新的授权、需求变化、异常处置必须明确决定。
5. 结束后审查本轮文件差异并自行提交版本；沉淀只采纳准确、有限定条件的规则。不要因为页面显示完成就直接部署到生产服务。

## 使用边界

| 可以纳入基础使用 | 暂不纳入 |
| --- | --- |
| L0 文本；L1 本地受控代码变更；固定角色及串并行路径；最多一次同范围返工 | 任意动态 DAG、无限返工、无人值守执行 |
| 人工审阅过的本地前台构建、检查和测试命令 | 发布、升权、安装、进程管理、外部网络／数据库／云资源写入 |
| 原生确认、已有证据的文件交付、逐项采纳规则 | 用模型承诺代替权限边界；把源码可见测试当成黑盒验收 |
| 精确停止状态及未知运行的审计处置 | 把 PID 消失、人工结束或 Agent idle 当成整个进程树已停止 |

引擎的累计预算解析默认仍关闭、scope 为空，不会悄悄修改旧实验 Profile。当前发布配置流程必须显式选择 `packaged-candidate`：为新运行启用 240 次模型请求、40 次命令和 30 分钟有效活动，Host 准入为 2 个活动根／根流与 4 个子角色。该配置已在隔离安装环境核验，但生产环境尚未启用；不能描述为所有 DSH 请求、Token 或费用都已封顶。额度和限制见 [资源策略](workflow-resource-policy.md)。

已整理[资源配置候选与离线基准命令](workflow-resource-policy.md)，但它不是已加载的配置。记账优化完成 30 分钟持续验证，后续 Host 并发候选完成同输入双轮 466/466；两者均尚未部署，不作为当前线上默认能力。新 `/workflow-resources` 入口也需要候选正式加载后才可用。

## 遇到异常

已验证的只读维护工具可生成 [一致性检查与脱敏报告](workflow-diagnostics.md)，不改变工作流状态；当前候选的安装后采集无需开发目录，仍须使用其固定 Host 和正确认证。报告需要处理或未完成检查时，不能据此声明健康、全 Host 空闲或允许重启；完整 Gate E 尚未关闭。

- **保存失败／超时，工作流尚未创建**：没有获得正式执行授权。先检查存储和会话服务，解决后重新提交；不手工补写 Journal。
- **正在停止**：等待托管范围回收；不要重复发起同一工作，也不要立即重启来隐藏状态。
- **未确认停止**：保留未知事实，核实旧运行影响；需要时走现有人工处置门禁。人工结束旧 run 不等于退出已证实，不能沿用旧授权继续。
- **writer 冲突／存储异常**：停止新工作，保留现场。不要删锁重试或覆盖数据库；核对进程创建时间、命令行及 owner，并先备份。
- **存储待恢复（候选）**：旧可信快照已撤下；停止请求不是退出证据。保留现场与备份，恢复可信读取后交叉核对原生会话、后台范围和文件，不因空列表或重启就宣称已停止。
- **角色执行异常（候选）**：先看原生调用错误与角色记录；异常不等于业务验收失败。需要重做时，停止本轮并重新确认后新建运行，不自动重试或消耗业务返工。
- **撤销未完成**：在原生输入框要求核对继续；每次恢复需新的确认。发现冲突时先保留用户当前内容、原始备份和 Journal，再人工比较，不能批量删除临时文件。
- **已撤销 · 待清理**：完成记录已有依据；可要求重试备份核对清理，不会重复恢复或覆盖目标文件。备份异常时保持挂起。
- **升级失败**：确认空闲且身份一致后回退已归档构建；保留当前数据。只有经过兼容检查的版本才能读取原记录，不能默认降级 schema。
- **历史角色目录不可读**：目录存在、Journal 可读都不代表原生对话兼容。已知旧 v0／descriptor v2 组合不被当前 DSH 支持；保留原件，不改版本号或清除告警，需要专门迁移或隔离归档方案。见 [核验与边界](../validation/2026-09-20-native-history.md)。

本轮激活脚本是一次性、固定目标的维护程序，不是任意时间可重跑的恢复工具。下一次升级必须新建基线并重新取得需要的中断许可。

## 从当前版本到正式 Production v1，接下来

1. **完成发布与恢复闭环**：独立归档、首次配置、编号 RC 重配置／升级／兼容回退及 Web 启停已有证据；继续补正式版本方向、可分发诊断采集和旧原生历史处置。不回滚数据、不改写旧退出事实，也不重用已消耗的服务中断许可。
2. **核对最终资源与故障范围**：Gate B 既定恢复矩阵已通过；资源和故障候选仍未部署，用同一安装候选完成最终负载／配置验收后再安排有授权的接入。离线测试数和有限中断点不代表全部故障消失。
3. **独立真实使用与冻结交付**：核对模型连通性，在可恢复的真实项目中由非实现者完成需求补充、执行授权和失败返工；不再重复展示问卷。历史网络提示仍需核实，未改宿主网络配置。自动化和合成回放不能代替实际模型／独立用户证据，最后逐项复核 C/D/E 并冻结同一版本。

高级能力不作为这三项的前置条件。完整五组准入要求保留在 [生产计划](../design/workflow-production-readiness-v1.md)，不因缩小试用范围而将未完成的 Gate 改成通过。
